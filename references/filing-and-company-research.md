# 立案操作与海外企业查询

## 立案流程探测

每次交付申请材料，先确认机构、规则版本、管理分支机构和文书类型。用网络搜索定位机构官网的 filing / commence / case management / fees / contact / user guide 页面，核对是否为现行说明。搜索摘要仅用于定位，正式结论须打开原文；官方网页不可达时保留失败状态和人工核验路径。勿使用咨询草案或过期手册替代生效文本。

记录 URL、标题、访问日期、相关段落、页面状态与本案适用性。来源标签分别为“官方公开说明已读取”“页面只读实测”“需登录确认”“待机构书面确认”；可达不等于完成全流程实测。登录墙、验证码、付费或访问限制出现时遵循宿主认证与权限规则，不绕过。仅为探测不得创建案件、上传客户材料、点击提交、缴费或对外发信。

依次核查：账户与代理权限 → 新案入口 → 必填字段 → 主文与附件格式/大小/命名 → 对方送达及证明 → 缴费及到账 → 预览签署 → 提交回执 → 案号与补正。页面步骤仅写已观察到的按钮名称；不可见部分以官方手册或待确认项表达。区分机构收件、对方送达、缴费完成和规则意义上的启动日，不能将上传成功直接写作立案成功。

分别列机构提交与向对方送达的渠道。邮寄要求按当前官方指引和本案通知确认，不能照抄办公地址当收件地址；电子提交免纸质时写“不要求邮寄”及依据。缴费给官方支付入口和费用取值日，不从旧模板复制银行账户。费用未知不阻止编制草案指引，但必须列为提交前阻塞项。

从 `assets/sources-registry.json` 中当前机构的 filing 字段读取渠道线索，再用当前官方说明核对。无登记时先发现官方来源并登记；无线上入口不推定不能立案，按官方确认的邮箱、邮寄或其他方式编制指引。指引使用 `assets/templates/04-立案申请指引.md`，本案操作记录只存案件目录。

## company_research 能力槽

该槽与 `party_data` 分工：前者查证外部登记信息，后者保存用户材料与主张。默认降级可用，不增加冷启动必答题。

1. 发现已安装的企业信息 MCP／API。邓白氏及类似服务仅作候选，不凭品牌名称宣称已绑定。验收需记录工具名、供应商、覆盖法域、权限/订阅、检索字段、最近成功查询时间、结果来源与更新时间；用最少的企业名称或注册号做只读查询，服务不可用时进入官方登记降级。
2. 优先按注册号与注册地精确匹配，再核对法定名称、历史名称、法律形式、状态及注册地址。同名企业、母子公司、分支机构分别列候选，不能自动合并。商业数据库 ID（如 D-U-N-S）不等同法定注册号。
3. 商业数据库与官方登记冲突时列出两者日期、范围与证据，说明待核事项；不能用第三方报告替代认证登记摘录。注册地址不当然是合同约定或仲裁有效送达地址，董事也不当然有本案授权。
4. 无 MCP 时按注册法域定位官方机关；不能因公司经营地在某国就查错登记机关。公开检索、登录查询、付费摘录分别说明。无结果不等于企业不存在；记录搜索名、语言、注册号和数据库覆盖限制。
5. 查询结果保存为案件目录中的主体核验记录：字段／用户材料值／外部登记值／来源 URL 或报告标识／查询时间／匹配依据／差异／待确认事项。不把个人住址、证件号等非必要信息加入公开交付；跨境传送前识别数据来源地、接收方和必要范围，交适用法律核验。

## 官方入口导航

按目标注册法域在 `assets/research-sources.json` 中定位官方企业登记通道。无预置通道时，先定位该法域及相应州、省或地区的登记主管机关，再核对名称、权限、访问与付费条件；不得按其他法域的组织结构猜测入口。登记与正文验收分开，未取得结果不推定企业不存在。
