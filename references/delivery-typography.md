# 交付排版规范

> 使用定位：本文件是方法与检索线索，不是已核验的本案法律依据。机构版本、条号、期限、金额、站点及 MCP 状态须在使用时回到官方文本和本机能力复核；无法核验的具体结论不得直接写入定稿。

本文件是 `12-delivery` 与各文书子技能共用的唯一排版依据。渲染器 `scripts/render_docx.py` 无第三方依赖（zip + OOXML），
在受限企业机上也能运行；排版能力等于本文件所写的方言能力，**不写进草稿的内容不会出现在 Word 里**。

## 一、命名与配对

| 项 | 规则 |
|---|---|
| 文书草稿 | `<案件目录>/deliverables/<序号>-<文书英文名>.md` |
| 交付文书 | 同名 `.docx`，`--mode legal` |
| 中文审阅说明（仅非中文文书） | `<文书名>-中文审阅说明.md` / `.docx`，`--mode memo`；文书本身为中文时不出本件 |
| 段落清单 | `<文书名>.paras.json`（`--manifest` 产出，核验交叉引用用） |
| 缺一份（非中文文书未配说明） | 视为未完成（铁律 5），`verify_suite.py` 会报 PAIR 失败 |

文件名不写对方当事人全称与争议标的细节（铁律 8）；案号或代号足够定位即可。

## 二、草稿方言

### 文件头（唯一被识别的键）

```markdown
---
title: Request for Arbitration
case: [[稳定案件代号]]
mode: legal
footer_left: ICC Case No. [[xxxx/xx]] — Draft [[v1]] — [[date]]
keep_sources: false
toc: true
---
```

只有 `title`、`case`、`mode`、`footer_left`、`keep_sources`、`toc`、`pair` 七个键生效。
`case` 只写本案稳定代号：交付闸门把该值与 `.arbitration-config.md`、`case.json` 与案件矩阵逐字比对，写成"当事人对名＋机构案号"或任何带描述的形式会被判"案件代号不一致"；机构案号、对手方简称与文书描述一律放 `title` 或 `footer_left`。
文号、语言、日期等元信息写成正文首段或用 `--header` / `--footer` 传入，**不要自造键指望渲染器识别**。

### 块级

| 写法 | 效果 |
|---|---|
| `# 文本` | 居中大标题（黑体/Times 加粗，14pt），不进目录 |
| `## / ### / ####` | Heading1/2/3，带大纲级别，进目录，构成长路径（`I. THE PARTIES > A. The Claimant`） |
| 普通行 | **自动编号段落**（Word 编号，非硬写数字），两端对齐 |
| `1. / 2.` 显式编号行 | 逐行独立成段，编号沿用 Word 序列；连续两行不会被并成一段 |
| `~ 文本` | 取消该段自动编号（用于引文、地址块、签名块） |
| `- 文本` | 项目符号段 |
| `> 文本` | 缩进段（条款原文、判词摘录） |
| 竖线表格 | Word 表格；列宽按内容长度加权，表头灰底。**单元格内的竖线必须写 `\|`**（渲染为字面竖线），来源标记放进单元格时就靠它：`[source:id \| 版本 \| 条号或段落 \| URL \| 校验 日期]` |
| `<pagebreak>` | 分页符 |
| `#! 文本` | **模板填写指引行**：只给起草人看，渲染时整行丢弃，绝不进入 Word。技能包 `assets/templates/` 里的逐段指引一律用此前缀 |
| 空行 | 结束当前段（跨行续写同一段落必须不留空行） |

### 行内

| 写法 | 效果 |
|---|---|
| `**粗**` `__粗__` | 加粗 |
| `*斜*` `_斜_` | 斜体 |
| `[[待填内容]]` | Word 中渲染为 `[待填内容]` + 黄色高亮，并计入占位清单 |
| `[source:<id> \| <版本> \| Art./Rule <n> \| <URL> \| 校验 <日期>]` | 灰色 9pt 斜体；`mode: legal` 下**默认自动剥离**，要保留须在文件头写 `keep_sources: true`；`mode: memo` 下默认保留，要强行删除加 `--strip-sources` |

## 三、渲染器行为要点

- 页面：A4，边距上/下 2.5cm、左 3.0cm、右 2.5cm（twips 常量固定在脚本内）。
- 字体：西文 Times New Roman；中文正文宋体、标题黑体。`legal` 正文 12pt，`memo` 11pt，行距 1.5 倍等效。
- 编号：走 Word `numbering.xml`，因此对方与仲裁庭可直接用 "paragraph 12" 引用；**硬写 "1." 也会被识别为独立编号段**，两种写法不要混用同一段。
- 目录：`--toc` 在文首插入 TOC 域并置 `updateFields`，Word 打开时自动填充；`#` 级标题不入目录。
- 页眉/页脚：`--header` / `--footer` 优先，否则页眉取 `case`、页脚取 `footer_left`（`legal` 模式缺省回落为 `case`），页脚含页码与总页数域。
- 段落清单 `--manifest`：导出 `numbered_paragraphs` 总数、`headings` 与每段 `{no, path, text}`，是中文审阅说明里"逐段填写要点"的编号来源。

## 四、法律文书（mode: legal）排版规则

1. **首块是当事人标识块**，逐行 `~` 取消编号：全称 → 法律形式与注册地 → 送达地址 → 代理人；随后一行 `Claimant` / `Respondent`，两者之间用 `versus`（核验器会把它当作物名一致性检查项）。
2. **一段一事实**。事实段不出现法条，法律段不复述事实，金额段不论责任；这样对方逐条答辩、仲裁庭逐段引用都不会错位。
3. **条款原文与函件摘录用 `>` 缩进段**，前后各一句出处与附件号。
4. 金额一律「币种 + 数字 + 期间」，日期一律 `31 January 2026` 或 ISO 二选一并全文统一（术语一致性见 `references/glossary-en-zh.md`）。
5. 主文（Request for Relief / Relief Sought）用独立编号段逐条列出，每条自带币种、起算点与期限，可执行化。
6. 未从用户材料取得的一切信息写成 `[[占位]]`，**不得推测填充**（铁律 3）；`--strict` 会因存在占位以退出码 3 拦下交付。
7. 签名块、附件索引、送达说明用 `~` 段落放文末。
8. 表格用于对照类内容（争点—依据—证据—待补），单元格内不写长段落。

## 五、《中文审阅说明》（mode: memo）固定五节

```markdown
## 一、本文件作用与程序依据
## 二、逐段填写要点
## 三、我方立场与可选表述
## 四、风险与待用户确认事项
## 五、给管理层的三句话汇报
```

- 第一节：说明这份文书在程序的哪一步、由哪条规则触发，每处规则引用带 `[source:…]` 标记（说明文件默认保留标记）。
- 第二节：按 `--manifest` 的段落号逐段讲"这段写给谁看、缺什么、错了会怎样"；引用英文文书时用 `paragraph <n>`，`verify_suite.py` 会检查该编号是否落在真实区间内（XREF）。
- 第三节：给出可选表述及其对置后果（强硬/中性/保留），并写对方最可能的反驳与仲裁庭关注点（铁律 7）。
- 第四节：所有 `[[占位]]`、所有推断值、所有需用户确认事项列成可勾选清单；同时指向《补充材料与信息确认清单》。
- 第五节：三句话——现在在哪一步、这周要交什么、最大风险是什么。不写形容词。

## 六、命令与退出码

```bash
python3 <suite>/scripts/render_docx.py --in <draft.md> --out <draft.docx> \
    --mode legal --toc --strict \
    --header "<案件代号 | 文书名>" --footer "<Draft v1 — [[date]]>" \
    --manifest <draft.paras.json>

python3 <suite>/scripts/verify_suite.py --workdir <交付目录> --mode submission
```

| 退出码 | 含义 | 处置 |
|---|---|---|
| 0 | 渲染成功 | 继续 |
| 2 | 输入缺失、`mode` 非法或依赖问题 | 修草稿或补路径 |
| 3 | 仍有 `[[占位]]` 未填（仅 `--strict`） | 出《补充材料与信息确认清单》，本轮不交付 |

`verify_suite.py` 检查项：**PAIR**（文书—说明配对）、**FILL**（占位是否残留）、**CITE**（引用是否带来源标记）、
**XREF**（`paragraph n` 是否落在真实编号区间）、**CONSIST**（当事人名称、金额、日期跨文件一致）、
**DOCX**（包内必备部件完整，装有 `xmllint` 时逐部校验 OOXML schema）。任一项未通过即不得对外交付；报告原样贴给用户。

## 七、降级路径

| 缺失 | 表现 | 降级做法 |
|---|---|---|
| `docx_render` 槽未绑定 | 无法出 Word | 只交 `.md`，并写明"用 Word 打开另存/粘贴到模板"的具体步骤；说明文件照出 |
| 无 `xmllint` | DOCX 结构校验只查部件与 zip 完整性 | 人工打开一次确认目录与编号显示，记入风险项 |
| 无网络 | 规则文本未取得 | 不得引用条号；文书中相关处改为 `[[适用规则条号待官方文本核对]]` 占位，走 `data/official/` 人工补录 |
| 中文环境字体缺失 | 宋体/黑体被替换 | 交付时提示Word将回落到系统中文字体，必要时在 `styles.xml` 层调整 |

## 八、禁止事项

- 不把案件材料写进技能包目录或 `data/`（铁律 8）。
- 不在交付版 `.docx` 里保留内部标签或开发期说明；正常法律引注及依法必要的第三方署名保留，不能把来源清理当作删除合法引注。
- 不用软回车假装段落——编号会断裂，交叉引用会错。
- 不在 `legal` 模式里用无来源标记的规则引用（铁律 2）。

## 写作与阅读负担

排版前按 `references/legal-writing-workflow.md` 做结构与语义回查。标题保持同页、与后段相连；段前段后留白由样式统一实现。字体与字号先遵守程序要求，风格偏好不取代强制规范。

一条来源标记只挂一个来源 id；同一句依赖两份来源时，分别写两个完整 marker。URL 不写“同上”；ID 与 URL 须对应登记条目。

配对义务以铁律 5 为准，本文件不复述：只有**非中文**对外文书才配《中文审阅说明》，中文文书不配。内部立案清单、办理指引或计算台账可在记稿 frontmatter 标 `pair: false`；渲染会登记，核验明确输出内部件豁免，仍检查来源、占位、结构和同步性。不得为对外文书使用该豁免。
