# MCP 接入向导

目标是让用户取得本轮所需检索能力，而不是让用户学习配置语法。先读 research-personalization.md 的能力与选择范围，再按本页执行；不要求新用户配置全部数据库。

## 1. 最少提问与复用

先看当前宿主可调用工具及用户指定的 research-profile.json。已连接、已选择的服务直接验收，不重复安装。还不能确定时一次问：“你用哪个客户端（含本机/远程）、希望接哪项已有数据库？配置只用于本项目还是长期使用？”法域与任务已有则不问。展示推荐方案与预计需用户完成的动作，例如“使用已有 LDH 连接；你只需完成一次登录，我来检查检索和全文”。不承诺固定耗时或全自动。

使用 `mcp_onboard.py inspect` 查看运行时；仅当用户指定或明确同意配置目标时读取该文件。命令存在只表示可执行文件在 PATH，不据此认定用户使用该客户端。云端 Agent 的文件不是用户电脑配置；无法访问用户设备时交付适配片段和逐步指引，不谎称已安装。

## 2. 选择接入方式

| 情况 | 路径 | 用户只需做什么 |
|---|---|---|
| 宿主已有插件/连接 | 检查工具列表、权限及目标法域验收 | 必要时完成官方认证 |
| Cursor 本地 JSON | prepare → apply → 客户端启用 → 验收 | 确认作用范围；完成认证/信任 |
| Claude Code 项目配置 | 已核实版本的 .mcp.json 或原生 mcp CLI | 完成项目服务信任与认证 |
| VS Code Local harness | 明确选择 .vscode/mcp.json 的 servers 格式 | 启用服务并完成认证 |
| VS Code 其他 harness | 按该 harness 当前文档/原生界面 | 不将 Local 配置格式机械套用 |
| ChatGPT、网页连接器、Claude Desktop、Codex 或其他客户端 | 优先宿主插件管理；否则查当前官方接入说明/本机 CLI help | 在原生认证界面登录；必要时提供客户端版本 |
| 只有数据库网页订阅 | 配置为 web 或 manual-export 后端 | 登录官方站点或提供获授权导出 |

JSON 写入助手只支持表内明确列出的三种格式；不编造所有客户端通用 JSON。含 JSONC 注释、TOML、环境变量/动态认证头或企业托管配置时，助手明确停止直接改写，改走客户端原生编辑器/CLI，保留原文。没有 MCP 的商业数据库仍可进入同一研究流程，不要求用户另购接口。

## 3. 核验接入规格并准备变更

从供应商当前官方文档确认 URL/包名、传输类型、认证、支持客户端、运行时和使用权限；登记表仅是线索。不要按国家名拼接包名，不自动尝试来历不明的安装命令。对于 stdio，说明首次启动可能下载/执行服务包；按用户已有授权及宿主权限继续，不额外设置每一步确认。真正缺少授权时，先准备具体服务、命令和变更范围再询问。

在用户指定的私有配置目录创建 server-spec.json（不放公开仓库）。例：

```json
{"type":"http","url":"https://legaldatahunter.com/mcp"}
```

对于经核实的本地服务，用 type=stdio、command 和 args 数组表达，不拼 shell 字符串。工具不会执行该命令；由宿主原生管理器在授权后启动。需要 Key 时优先宿主密钥存储或官方输入界面；不要让用户把密码/Key贴进聊天，不写入计划、日志、项目仓库或来源登记表。复杂凭证配置使用原生界面，不能偷偷简化成无认证连接。

```bash
python3 <suite>/scripts/mcp_onboard.py inspect --target <用户指定配置.json>
python3 <suite>/scripts/mcp_onboard.py prepare --client cursor --target <用户指定配置.json> --name legal-data-hunter --spec <server-spec.json> --plan <setup-plan.json>
python3 <suite>/scripts/mcp_onboard.py apply --plan <setup-plan.json> --receipt <setup-receipt.json>
```

先展示具体新增/替换服务规格和目标范围，不输出原配置内其他服务的凭证。默认同名不同配置报冲突，优先另取别名；确定要替换才重新 prepare --replace。同名且配置一致不重复写入。准备后目标变化会拒绝应用，重新读取并合并。只保留本服务变更，原有服务及其他顶层字段不丢失。

apply 自动保存私有备份和回滚凭证，原子替换文件；备份可能包含原配置里的密钥，必须保持私有，不上传仓库。配置文件落盘只到 CONFIG_WRITTEN，不能宣称连接成功。

## 4. 启用、认证与分层验收

告诉用户当前只需执行的下一步，不一次抛出整套技术清单。通过客户端原生界面启用/重载，并按宿主提供的认证流程完成 OAuth、账户选择或 API Key 绑定；不要代用户接受付费订阅或绕过管理员限制。没有认证能力时清楚交接，保留进度；用户回来后从该步继续，不重走冷启动。

按顺序记录状态：SELECTED → PREPARED → CONFIG_WRITTEN → AUTH_REQUIRED（如需）→ TOOLS_DISCOVERED → ACCEPTED/PARTIAL。每一步只依据观察到的结果前进。

1. **连接**：读取客户端实际状态与脱敏错误。不能用 HTTP 200 或安装成功代替 MCP 初始化。
2. **工具**：通过宿主取得实时工具名称与参数 schema；不得根据旧文档猜调用。
3. **覆盖**：确认本案法域、资料类型、日期、法院层级以及付费范围；无发现工具时读供应商覆盖说明并记限制。付费通道的资费、免费额度与请求配额只现场核对并告知查询入口，不写入登记表或技能包——选哪一档由用户在配置时自行决定。
4. **搜索**：用不含客户信息的公开问题检索，保存工具、参数、结果标识和查询日期。
5. **全文**：取一个搜索命中的原文，核对标题、日期、官方链接或稳定文献 ID及段落；登录页、摘要和报错不算全文成功。
6. **按需能力**：需要引注定位或后续处理时分别测试；没有相应工具则仅标该项不可用，不强制阻断已可用的搜索。

在 research-profile.json 的对应 provider 更新 status 与 acceptance（目标 capability、jurisdiction、date、result、evidence），日志保存在用户私有配置目录或案件目录。仅通过项可写 passed，其他项保留未验收；整套验收记录不能复制到未测试法域。用 research_profile.py select 复核本轮实际可选能力。验收自动调用须通过真实宿主工具，本地助手不伪造远程测试结果。

用户回执示例：“已接入 A：新加坡案例搜索、全文通过；后续裁判处理未覆盖。配置用于本项目，原有服务保留。现在可以开始本案检索。”若只写好文件：“配置已生成，尚需在客户端启用并登录；我还未验证检索可用。”

## 5. 故障恢复与回滚

| 观察到的现象 | 下一步 |
|---|---|
| 401/认证失效 | 原生认证界面重新登录；保留配置，不自动重装 |
| 403/组织禁止 | 分清订阅权限、管理员限制与网站拦截；使用已授权替代，不绕过 |
| 找不到 npx/uvx 或启动失败 | 核对客户端继承的 PATH、运行时和官方包名；给对应系统安装路径，不先删配置 |
| 工具未出现 | 查服务启用、项目范围、信任、重载及日志；不盲目新增重复服务 |
| 429/配额不足 | 说明限额，按可见重试信息稍后再试或选已授权后端；不自动升级付费 |
| 搜索有结果但无全文 | 记 PARTIAL，区分订阅缺口、来源缺失与抓取失败 |
| 无结果 | 调整语言/条件并核覆盖；不认定不存在法律或案例 |
| JSONC/TOML/未知客户端 | 保留文件，转原生编辑器/当前官方指引 |
| 本地配置写入后失效 | 核对目标路径与实际运行宿主是否同一环境 |

```bash
python3 <suite>/scripts/mcp_onboard.py rollback --receipt <setup-receipt.json>
```

回滚仅在配置仍与本次写入哈希一致时恢复备份；如果用户后来改过，拒绝整文件覆盖，人工合并移除本次条目。记录恢复状态，避免删除其他服务。网络失败不要无限重试，给一条当前可执行的下一步与替代路径。
