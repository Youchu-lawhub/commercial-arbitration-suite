# 机构规则核验清单 Forum Rules Verification Checklist

> 本文件不保存任何机构的规则结论、条号、天数、金额、费率、默认人数或"有无某机制"的判断。
> 它只规定：办任何一个程序动作之前，必须从哪一个官方版本、用什么问题、取得什么文本证据。
> 具体答案一律在运行时从官方文本取得；未取得文本即不得写入文书、程序令或对客户的确定性答复。

## 一、为什么是清单而不是对照表

机构规则会换版，条号会漂移，机构网站公布的金额与期限也会单独调整。把结论预先写进技能包，等于把旧版记忆当成现行法。
因此本套件只保留三类内容：

1. **可验证的来源登记**：`assets/sources-registry.json` 记录机构、规则版本、官方入口、访问状态与校验日期。
2. **可复核的检索定位**：`assets/rule-anchors.yaml` 按机构逐条登记条号级定位，只有已在该版本文本的官方全文中命中过的条目才进入该表；未取回官方文本的机构不登记。
3. **可重复的核验流程**：本文件的十二维问题表、命令与来源标记格式。

任何机构的具体规则，只有同时满足"官方来源可访问 + 本案适用版本可确定 + 原文命中"三项，才允许进入交付物。

## 二、单次核验流程

```bash
# 1. 由仲裁启动日与条款约定确定适用版本
python3 <suite>/scripts/fetch_official.py applicable --inst <机构> --commencement <YYYY-MM-DD>

# 2. 取回该版本官方文本（站点不可达时按降级路径处理并记录）
python3 <suite>/scripts/fetch_official.py fetch <source-id> --to-md

# 3. 用问题关键词在该版本文本中定位；未命中不等于不存在
python3 <suite>/scripts/fetch_official.py lookup <source-id> --pattern "<关键词>" --max 5

# 4. 检查已登记锚点是否换版、是否过期
python3 <suite>/scripts/fetch_official.py anchor --inst <机构>
```

判定只有四种，不得混用：

| 判定 | 含义 | 可以怎么写 |
|---|---|---|
| `HIT` | 在**本案适用版本**的官方文本中命中原文 | 可写入，附来源标记与命中位置 |
| `NOT_FOUND` | 已取得该版本全文，但关键词未命中 | 只能写"未检索到"，不得写"规则没有规定"；换关键词或人工通读 |
| `NO_TEXT` | 官方文本未能取得（站点不可达、只有 HTML、扫描件无文本层等） | 条号与数值写占位，披露"未核验最新规则可适用性"，继续完成其余工作 |
| `VERSION_UNKNOWN` | 无法确定本案适用版本（启动日不明、条款约定与机构版本冲突） | 先向用户确认；两说并记，不得静默取其一 |

`NOT_FOUND` 与 `NO_TEXT` 都不是"机构无此机制"的证据。否定性结论只能来自对该版本全文的完整核对，并须写明核对范围。

## 三、十二维核验问题表

对每个机构、每个适用版本，按下表逐维取文。问题栏是必须回答的内容，不是预设答案。

| 维度 | 必须从官方文本回答的问题 | 主要落点 | 禁止直接采用 |
|---|---|---|---|
| 启动 | 仲裁何时开始？以谁收到什么文件为准？形式瑕疵如何补正？立案费未缴的后果是什么？ | 04-commencement 时限台账 | 旧版起算点、二手流程图、他机构口径 |
| 首轮文书 | 答辩、反请求、抵销与管辖异议的期限及起算点？延长须谁批准、须附什么？ | 05-defence 日历 | "通常""一般"之类未命中原文的表述 |
| 组庭 | 未约定人数时如何确定？提名、确认、替换与僵局处理分别由谁决定？ | 06-tribunal 组庭方案 | 机构所在城市=默认仲裁地、当然三人庭等推断 |
| 管辖权 | 管辖权异议由庭、机构还是法院决定？最迟何时提出？机构阶段审查到何种程度？ | 03-forum-rules 答复、05-defence | 把机构表见审查写成终局结论 |
| 临时措施 | 仲裁庭可采取哪些措施、以什么形式？法院协助是否需要先向庭申请？紧急机制是否适用本案协议与版本？ | 07-measures-costs | 把其他机构的紧急仲裁员机制套用过来 |
| 证据与披露 | 规则是否规定披露请求、证人、专家与秘密材料处理？软法是否须当事人合意并入？ | 08-evidence 程序令 | 把 IBA Rules 当成自动适用 |
| 快速程序 | 触发条件、计算口径、排除方式、独任是否强制、裁决期限如何另计？ | 04/05/06 程序轨道 | 只凭争议金额承诺适用或排除 |
| 费用 | 行政费与仲裁员报酬如何计？预缴、分期、未缴后果与费用担保分别是什么？ | 07-measures-costs 预算 | 旧费率表、按比例估算的"大概费用" |
| 裁决 | 裁决期限从何时起算、可否延长？是否须机构核稿？签署、送达与生效要件是什么？ | 09-hearing 倒排、10-award-post | 庭签署日=当事人收到日 |
| 裁决后救济 | 更正、解释、追加裁决与发回的可用性、申请人与期限？ | 10-award-post | 默认各机构都有同样救济 |
| 合并与追加 | 合并由谁决定、标准是什么？追加的最后时点？多合同能否单案处理？ | 03/06 程序结构 | 把关联合同当然视为可合并 |
| 期间与递交 | 期间按谁的时区、什么时刻、何种送达方式计算？份数与递交渠道？节假日如何顺延？ | 全流程时限日历 | "多数机构"式概括、按本国习惯计算 |

条款起草（02）不另设第十三张表：上述十二维中任何一项会改变条款设计的，都必须在条款体检表中写明"依哪个版本、哪一条、核验日期"，否则只能写待确认。

## 四、机构差异只有在同一版本内才可比较

比较两家机构前，先分别完成第三部分的取文。比较表只能包含以下三类内容：

1. **已核验差异**：两侧都有官方原文命中，附各自 source-id、条号与校验日期。
2. **待核差异**：一侧或两侧未取得文本，写"待核"，不得用"似乎""通常"填充。
3. **不可比事项**：规则体系不同（机构规则 / 仲裁地法 / 软法）、版本不同或计算口径不同，单列说明，不作优劣判断。

禁止：

- 用一家机构的门槛推算另一家；
- 用旧版条号解释新版规则；
- 把机构网站的宣传性描述当作规则义务；
- 把"未检索到"写成"没有该机制"；
- 在未确定适用版本前回答"程序会怎样走"。

## 五、来源标记与交付

每次写入文书、程序令或客户答复的规则内容，必须带同一格式的来源标记：

```text
[source:<source-id> | <规则版本/生效日> | <条号或附录> | <官方URL> | 校验 <YYYY-MM-DD>]
```

同时满足以下条件才算可交付：

- `source-id` 存在于来源登记表，且本案适用版本与登记版本一致；
- 官方文本已实际取得（本地缓存或人工保存的官方文本），不是仅凭搜索摘要；
- 条号与命中短语能在该文本中复核；
- 校验日期在刷新周期内；超期须重新取文，不得沿用旧标记；
- 机构规则与仲裁地法、软法分别标记，不互相替代。

## 六、访问受阻时的降级路径

| 情形 | 处理 |
|---|---|
| 官方站点 403、超时或反爬 | 改用浏览器人工打开官方页面，保存正文与截图、访问日期；仍无法取得则按 `NO_TEXT` 处理 |
| 只有 HTML 页面 | 保存可见正文并注明页面地址与访问日期；不得把导航、挑战页或摘要当条文 |
| 只有扫描件 | OCR 后对照原图；无法确认文字时按 `NO_TEXT` 处理 |
| 机构要求登录或付费 | 不绕过访问限制；请用户提供其合法取得的官方文本，并记录来源与取得方式 |
| 规则版本存在过渡期 | 同时记录旧版与新版，按启动日、条款约定与过渡条款分别判断；无法判断时列为待确认 |
| 机构规则与仲裁地法冲突 | 分别取文，列出冲突点，交 11-governing-law 或当地律师；不得自行择一 |

## 七、维护

- 来源与版本变化：更新 `assets/sources-registry.json`，运行 `fetch_official.py report` 查看过期与不可达项。
- 锚点变化：只有在新版官方文本中重新命中后，才可更新 `assets/rule-anchors.yaml` 的 `locator`、`checked_at` 与 `via`。
- 静态规则检查：运行 `python3 <suite>/scripts/rule_audit.py`。扫描范围是根 SKILL.md、suite.yaml、references、skills、assets/templates 与 assets/institutional-knowledge；拦截未绑定的条号／天数／金额／门槛（含中文数字与条号区间写法、人民币与万元金额、中文数字期限）、默认机制表述、`references/institution-rule-versions.md` 与登记表的列值漂移，以及国别执行结论与择地推荐（公约成员身份、成员数量、对某一法域执行优劣的定性排序、指向"更友好"法域或法院的推荐语——这一类同行带来源标记也照样拦截）。登记表条目同样在扫描范围内：`note` 一类说明文字不得复述条号，条号只写进 `assets/rule-anchors.yaml`。
- 本文件自身不得新增机构行、条号、天数或金额；需要记录具体结论时，写入案件目录的核验记录，不写回技能包。

| 文件 | 负责 | 不负责 |

| 本文件 | 提问、取文、判定与来源标记流程 | 任何机构的具体答案 |
