## 一、接入与最小事实
先读现有合同、往来和用户目标，回答“要恢复什么商业状态”，不要把争议预设为欠款。
交易类型用于发现遗漏，不是法律定性、请求权基础或固定举证树。
允许同时选择多个类型；无法归类用 `other`，跨类型组合用 `mixed`，写明实际结构。
先画主体—合同—履行—资金—资产关系；签约方、履行方、收款方和受益人分别识别。
记录合同层级、补充文件、订单并入、背靠背安排及各自仲裁与选法条款，不凭交易关联合并程序。
从已有材料提取当前阶段、争议行为、关键时间、受影响业务和期望救济；未知不填默认值。
时限风险先提示并安排核验；工作截止与法律届满分别记录，不编起算日或期间。
纯答辩、协议体检、非金钱请求和执行预判直接接入对应任务，不要求先建立付款请求。

## 二、交易类型检查表
每行依次使用“核结构→取材料→开争点”；下列均为待核问题，不是某法域规则。

| 类型 | 核结构与首批材料 | 优先展开的争点与救济问题 |
|---|---|---|
| 买卖 | 标的、规格、订单、交付与检验、风险安排；取合同、收货及异议记录 | 是否符合约定、风险何时转移、付款条件是否实现；比较修补、更换、减价、终止、赔偿 |
| 制造 | 定制设计、模具、工艺与批准权限；取技术版本、样品、批次与测试记录 | 设计责任还是制造缺陷、变更是否授权、返工是否可行；模具交还和技术保密能否请求 |
| 经销 | 区域、独家性、指标、库存及客户关系；取渠道协议、订单和销售记录 | 独家范围、渠道冲突、最低采购、退出库存与客户交接；勿把经销自动认定为代理 |
| 供应链 | 多层采购、替代来源、预测与承诺、依赖节点；取主协议、排产及中断日志 | 短供归因、预测是否承诺、替代采购与减损、连锁损失；上游违约是否影响下游义务 |
| 工程 | 总分包、设计采购施工界面、里程碑与变更权限；取图纸、签证、进度及验收档案 | 工期延误、并发原因、变更计价、性能与缺陷、终止交接；工程继续履行是否实际可行 |
| 能源 | 供量、计量、调度、定价及许可接口；取项目协议、运行数据和监管文件 | 供能中断、最低提取或供应、价格调整、政策事件分配；持续供应及设施使用救济另核 |
| 航运物流 | 承运、货代、仓储与多式联运角色；取运输单证、交接、轨迹及货损检验 | 责任区段、货物控制、迟延与货损、留置或放货基础；先识别真正合同方及可适用责任制度 |
| 借款融资 | 贷款、授信、租赁或其他融资结构；取提款、条件、财务承诺及通知记录 | 是否实际放款、条件违背、加速到期效力、费用和利息；通知及补救要求逐项核验 |
| 担保 | 保证、独立保函、抵押或质押分别识别；取担保文本、权限与设立公示材料 | 从属性、索赔条件、责任范围、抗辩及财产优先性；担保人责任不自动来自主合同 |
| 合资 | 公司、合伙或合同合作结构；取章程、股东协议、决议和出资记录 | 治理权限、僵局、信息权、出资、关联交易及退出；公司本身与股东请求分别构建 |
| 并购 | 股权或资产交易、签署交割分离与调整机制；取披露、条件清单及交割账目 | 先决条件、陈述保证、价格调整、赔偿限制与解除；防止调整款和同一损失双重计算 |
| 许可技术 | 权利范围、地域、领域、版本、改进及再许可；取权属链、许可和使用日志 | 超范围使用、技术交付、性能、保密与退出删除；合同请求与权利有效性问题分流 |
| 服务 | 成果型或持续服务、服务水平、验收和依赖事项；取工作说明、工时及交付记录 | 服务不达标、范围变更、客户配合、成果归属；重做、交接、停止使用与赔偿分别考虑 |
| 保险 | 险种、被保险利益、承保期间和索赔主体；取保单、批单、通知及理赔材料 | 承保触发、除外、披露、减损、代位与其他保险；保险赔付和基础损害回收须协调 |
| 数字平台 | 平台、商户、用户及支付服务角色；取条款版本、同意记录、算法或交易日志 | 封禁、排序、数据访问、账户结算、知识产权与服务连续性；监管及可仲裁性不得略过 |
| other / mixed | 写明无法套用的业务环节，按合同与实际控制拆分；保留各方角色和证据 | 按独立义务与争议轴构建；竞争法、消费者、数据等强制规则作为额外研究问题 |

选中类型后，不要求用户一次补齐整行材料；只索取改变本轮决定的缺项。
同一交易可同时存在质量、治理和非金钱争议，主争点应来自事实而非合同标题。
行业术语、贸易条件与惯例仅是候选依据；核验是否有效并入、版本及与强制规则的关系。
保险、担保或背靠背责任另有条件，不把原交易结论自动传递给其他义务人。

## 三、争议轴与行动
每条轴单独标“涉及／不涉及／待核”，说明理由；“不涉及”不能代替未调查。

| 争议轴 | 必须回答的问题 | 当前动作 |
|---|---|---|
| 付款 | 何义务、何条件、何时到期、谁向谁给付；是否存在抵销或付款抗辩 | 对齐合同、履行、结算和支付凭证；不由发票直接推定债权成立 |
| 履行质量 | 承诺标准是什么、偏差在哪里、由谁造成、是否通知与补救 | 保全样品、版本、验收与技术数据；核实专家及替代解释需求 |
| 终止 | 终止基础、程序和通知是否满足，终止前后义务如何分界 | 保存通知链与继续履行记录；分别研究终止有效性及后果 |
| 治理 | 权力来自何文件、何主体有权作决定、何行为受到挑战 | 核查决议、授权、信息权与章程；研究可仲裁范围及必要当事人 |
| 赔偿 | 责任、损失、因果、可归责范围及限制各是什么 | 建损失项目与证据对应表，核实减损、替代交易和重复项目 |
| 非金钱 | 要求何人做或不做何事，仲裁庭有无权限，第三人能否受约束 | 明确行为、范围、交付标准及履行条件，并移交执行可落地性核查 |
| 管辖 | 同意、主体、范围、程序前置、合并或追加基础是否存在 | 分离实体与管辖抗辩；核对每份条款及异议窗口 |
| 执行风险 | 主体、资产、救济形式和程序记录有哪些潜在障碍 | 引用 T- 目标并交 14；不以资产线索证明责任或可执行性 |

同一笔损失可能对应多个请求基础，分别证明后再处理竞合，不将其累计为多个独立损失。
同一事实在管辖和实体中可能承担不同作用；明确各自证明用途，避免互相替代。

## 四、请求、抗辩与证明链
1. 用一句话写本轮立场：谁因何行为，请求何种救济；纯答辩写争议命题和否认范围。
2. 分开合同准据法、仲裁协议准据法、仲裁地法、执行地法；具体方法见 `global-research-protocol.md`。
3. 从已核适用法抽取要件和例外，不按交易表预装固定要件；举证责任与标准另核。
4. 按 `case-construction.md` 关联 CL-/DF- → E- → F- → EV- → A- → R-。
5. 对单纯否认，定位对方要件不足之处；对积极抗辩，核验本方需要证明什么。
6. 把关键技术事实、商业背景和法律评价拆开，给每项事实保留原始材料页段。
7. 列最强反方解释、支持它的不利证据、己方回应及无法消除的风险。
8. 写出会推翻当前理论的新事实或新权威，以及调整请求或接受替代救济的条件。
9. 缺项登记 OQ、影响、负责人、工作截止及补证路径；用户预计答案不是已确认事实。
10. 复杂度按事实、合同、争点、法域和专业证据判定，不单按金额决定。

## 五、救济和回收设计
请求以商业目标排序：恢复履行、保有技术或渠道、退出合作、回收财产、补偿损失可并列比较。
每个 R- 写义务主体、行为或给付、范围、前提与可执行障碍；备位方案标清选择关系。
非金钱请求不强制填写本金、币种或利息；行为描述必须足够明确且能由相应主体履行。
金钱请求逐项核算本金、损失、利息和费用，列因果及合同限制，不用总额掩盖重复。
利息须先核法律及合同基础、计息口径与日期，工具计算不能反过来证明请求成立。
逐票分摊仅适合票据或往来账型债权，不强加给工程延误、治理或技术许可争议。
多币种原币分列；未确认汇率、日期、来源和适用口径，不合计或相互直接抵减。
付款、保险赔付、担保实现与各地执行回款在同一回收底账协调；冻结不是实收。
集团关联、控制或受益不当然构成责任；担保、共同责任和权属逐项证明。
时间紧迫时并行保全证据、研究临时措施和延长期限请求；未获准前不假定期限暂停。

## 六、交付与闸门
当前轮至少给出：争点地图、最强请求或抗辩链、关键缺项、下一行动与负责人。
轻任务只做需要的部分，不为凑表创建无关矩阵；执行目标主表仅在 `enforcement-plan.yaml`。
材料不足仍可研究、补证和形成受控草案；草案显著标不可提交并按根入口登记 `pending.json`。
占位 Q 与实质 OQ 分别跟踪，不能删除占位后假称实体问题已解决。
提交前逐项核事实、权威、计算、救济权限、对抗审查及所选 profile 的材料和矩阵闸门。
缺少关键依据即阻断受影响提交；用户同意、结构通过或工具退出成功均不能替代实质核验。
正式交付按根入口配对 Word 与中文审阅说明；外部专业意见和实际提交另需适当授权。
