## 〇、四条命令（先跑命令，再谈通道）

```bash
cd <suite>
python3 scripts/research_sources.py doctor                       # 本机有哪些运行时（node/uvx/pipx/docker…）
python3 scripts/research_sources.py report                       # 登记表全貌 + 过期项（age_days > 90）
python3 scripts/research_sources.py plan --jurisdiction <DE> [--layer <lex_arbitri>]   # 本案可用通道 + 闸门结论
python3 scripts/research_sources.py check [--id <通道id>]         # 逐条实测并写 data/_provenance/
python3 scripts/research_sources.py get --id <api或site通道> --param k=v --out <案件工作目录>   # 取一手文本落盘
python3 scripts/research_sources.py judge --url <候选URL> [--jurisdiction <DE>]  # 该域名能否充当本案法域的 tier 1 官方原文
```

- `plan` 是唯一的**选路出口**：它按法域过滤、按实测结论降级、按相关性排序，并直接给出接入 JSON 与验收 Prompt。
  不要凭本文件凭记忆推荐通道。
- `get` 只把正文写进 `--out` 指定的案件目录，且拒绝写进技能包（铁律 8）；同时落 `.provenance.json`（URL、时间、sha256、层级提示、caveat）。
- **`get` 判定响应体，不只看 HTTP 200**。200 后面可能是反爬壳、JS 载入页或整本扫描 PDF，把它们当"已取回条文"就等于绕过披露义务。三种结果各自要求：
  - `FETCHED`（附 `content_grade: ok`）：HTML 去标签后有足量正文、或 PDF 有文本层。仍须按来源分层定级，`verified` 恒为 false。
  - `FETCHED_SCAN_OCR_REQUIRED`：官方扫描件已存进案件目录，但**没有文本层、一个字条文都没读到**，故不附 `citation_stub`；先 OCR 再核对条号，在此之前按未取得一手文本处理。
  - `FETCH_FAILED`：壳页／空响应／非所声明的格式。**退出码仍为 0**，因为这是降级路径而非输入错误；须改浏览器取文或换通道，不得把本次下载当依据。
- `state` 为 `SECONDARY_ONLY`／`BLOCKED` 的通道是**官方检索门户**：`get` 直接拒绝并返回 `LOCATOR_ONLY_CHANNEL`。门户首页正文再多也没有条文，用它是去**定位**具体文件 URL，再以承载该 URL 的通道取文或走人工流程。
- 退出码 0 表示"可以继续工作"，**包括降级路径与未登记法域**；只有输入非法、登记表损坏、`--out` 落在套件内时才返回 2。
- `check`/`plan` 的实测结论有保鲜期：`plan` 会把 `GONE` 降为不可用、把 `UNREACHABLE`／被反爬挡住的通道**从可绑定名单里剔除**。
- `check` 的结论（`verdict`）决定 `plan` 是否继续把通道算作可用，各档含义不可混用：

| verdict | 含义 | plan 的处理 |
|---|---|---|
| `ALIVE` | 状态码与响应体都通过（免密通道还会记 `content_grade`） | 保持原状态 |
| `NO_TEXT` | HTTP 200 但响应体是反爬壳、JS 载入页或无文本层扫描件 | 降为仅定位，**不计入闸门** |
| `AUTH_OR_FORBIDDEN` | 401／403，须凭据 | 免密通道降为需鉴权 |
| `GONE` | 404 或包已下架 | 判为 DEAD，不得再绑定 |
| `UNREACHABLE` | 连接失败（含本机网络被过滤） | 降为 `BLOCKED`；须按三档口径判是反爬还是本地网络 |
| `TRANSPORT_MISMATCH` | 405／400／406：**本探测的请求形态不被接受**，不等于通道坏 | **不降级**；须在客户端里确认传输方式后重测 |
| `NOT_AUTO_CHECKABLE` | 该类通道无自动核验方式（如需先建库或参数化） | 不降级；按 `acceptance` 人工验收 |


## 一、闸门状态与本轮允许做的事

`plan` 返回的 `gate` 只有五个值，一一对应动作，不可自行放宽：

| gate | 含义 | 本轮可做到 | 必须向用户说明 |
|---|---|---|---|
| `CANDIDATES_REQUIRE_ACCEPTANCE` | 登记表列出本案法域候选通道，尚未完成当前环境正文验收 | 检索 + 交叉比对；两处一致才升"高置信度" | 明确说明尚待正文验收 |
| `CANDIDATES_REQUIRE_ACCEPTANCE` | 只有 1 条 | 检索，但境外法实体结论最高"中置信度"，并生成给外部律师的指示要点 | 交叉核验缺失（用 `disclosure` 原文） |
| `RUNTIME_OR_KEY_GAP` | 无免密通道，但有"装一下/给 Key 就能用"的通道 | 先按 `setup_gap` 补条件再跑 acceptance；补不了走 `retrieval_ladder` | 未取得一手文本（暂按 degraded 处理） |
| `NO_BOUND_CHANNEL` | 该法域已登记但无可自动取文通道 | 先走登记的浏览器／人工取文路径；没有则走 `retrieval_ladder` | 未取得一手文本，需外部律师意见 |
| `UNREGISTERED_JURISDICTION` | 本套件未登记该法域的任何通道 | 走 `retrieval_ladder`：取到官方原文即可照常引注；停在 tier 2／3 时只给程序框架与问题单 | 未登记通道；未取得官方原文前不下实体结论并转外部律师 |

`contextual-only`（公约、示范法、译本索引等跨法域页）**不参与闸门判定**，只作背景与交叉线索：
它不能充当本案法域一手文本的来源。仲裁地是德国时引 UNCITRAL 示范法，不等于核验了 ZPO。

### 无登记通道时的降级取文阶梯（`retrieval_ladder`）

登记表没有通道**不等于不能办这件事**。后三种 gate 的 `plan` 输出都带 `retrieval_ladder`，按证据力自上而下走，到哪一级就按那一级的引注权限写：

| tier | 方法 | 可作引注来源 | 边界 |
|---|---|---|---|
| 1 | 联网取官方原文（议会／司法部／官方公报／最高法院站点） | 可以 | 须记录官方 URL、法律全称与编号、条号、版本或生效日期；译本只作辅助 |
| 2 | 联网检索权威二次文献（机构国别报告、UNCITRAL／ICCA 资料、大型律所指南） | 不可以 | 只用于定位条号与争点方向，必须回到 tier 1 取原文才能写入文书 |
| 3 | 模型内置知识 | 不可以 | 只搭程序框架、争点清单与问题单；禁止凭记忆写条号、条文、期限天数或金额门槛 |

tier 1 有一个实测陷阱：搜索某国仲裁法全文时，排名靠前的往往是律所、文库或 NGO 转载的法律 PDF，
形式上就是完整条文，极易被误当作官方原文。**判定标准只看托管域名是否为该国官方机构，不看文件内容像不像正文**；
转载件一律降为 tier 2，只能用来定位条号。

这个判据不能靠自觉，用 `judge` 核：它读登记表里的 `official_hosts` 与 `non_official_hosts` 台账，
返回 `OFFICIAL`／`SUPRANATIONAL_OFFICIAL`／`OFFICIAL_OTHER_JURISDICTION`／`SUPRANATIONAL_NOT_APPLICABLE`／
`NOT_OFFICIAL`／`UNVERIFIED_HOST`，并给出 `tier1_allowed`。三条口径要记住：

1. **台账只收本套件自己实测过的域名**——`verified_text` 是"已从该主机取回过真实法律文本"，
   `official_pending` 是"已登记为该法域官方门户但尚未取回正文"。因此台账**故意不穷举**，
   它的价值在于每一个条目都有可追溯的取证通道（`via` 字段，安装器会校验该条目确实存在）。
2. **不在台账里的域名默认按 tier 2 处理**，即 `UNVERIFIED_HOST` 不等于"非官方"，更不等于"可以引注"。
   要升 tier 1 必须先实证该域名的官方身份（该国政府站点明示其为法律发布机关，或官方立法／公报站点链接指向它），
   确认后写入 `official_hosts` 并留 `evidence`。
3. **超国家文本对不适用法域不算一手依据**：`judge --jurisdiction NG` 问 OHADA 统一法会返回
   `SUPRANATIONAL_NOT_APPLICABLE`、`tier1_allowed: false`。同一道理，德国案引 UNCITRAL 示范法
   不等于核验了 ZPO——只有待证命题本身就是这部文书的内容时才算 tier 1。

## 二、按问题类型选通道（`--layer` 取值）

| 要解决的问题 | `--layer` | 现实说明 |
|---|---|---|
| 仲裁地程序法（组庭、临时措施、撤销裁决、法院介入） | `lex_arbitri` | 国别法律包普遍不含仲裁法；优先官方单条深链 + `fetch_official.py` |
| 合同准据法的实体规则（时效、违约金、免责条款效力） | `governing_law` | 免密官方成文法库可用作一手文本，判例层多缺 |
| 判例真实性、引注落地 | `case_law` | 美国走公开判例 API；其余法域以官方判例库为准 |
| 裁决承认与执行地的程序要求 | `enforcement` | 执行地法院要求高度本地化，默认转外部律师 |
| 条号／案号交叉核验 | `citation_check` | 与主通道必须来自不同提供方，否则不算独立第二来源 |
| 数据、出口、制裁等合规横切 | `compliance_crosscut` | 与仲裁程序无直接关系，只在披露／保密冲突时用 |
| 机构规则、软法指引（二次） | `procedure_secondary` | 译本与综述一律二次文献，不得充当引注来源 |

## 三、仲裁场景的现实（选路前先读这五条）

1. **高频仲裁地的第一手通道仍是最薄的一环**：
   **各层各法域当前处于哪个档位，一律用 `research_sources.py report` 的 `coverage` 字段查，本文件不抄名单**。
   名单一抄就会过期：新增一条通道或把某个域名改判，同一天里多个法域的档位都会跟着变。
   `coverage` 每个层次给出四档法域清单：`text`（有可绑定正文通道）、`gated`（须自有凭据或本地运行时）、
   `manual`（只有已登记的人工／浏览器取文路径）、`locator`（该法域只剩检索门户，没有正文——
   门户本身不进通道登记表，这一档来自 `check` 就地实测把某条通道降级为仅定位）。
   读结果时记住这四档对起草意味着什么：
   - `INDEPENDENT`（提供方与权威源都不同）才满足"两个独立来源"；
   - `PROVIDERS_OK_UPSTREAM_OVERLAP`／`SAME_UPSTREAM_ONLY` 是不同管道读同一份权威文本——
     能发现各自的抓取与条号错位，**不能发现该文本本身的版本问题**，重要命题仍须另找 upstream 不同的来源或降至 medium；
   - `SINGLE_PROVIDER` 不满足两条独立来源，境外法实体结论最高中置信度并出外部律师指示要点；
   - 加拿大按层各一条官方来源：联邦法、不列颠哥伦比亚省（温哥华）、安大略省（多伦多）。
     国际商事仲裁法在加拿大属省级立法，联邦法与省法文本不同、不能互相印证，
     `plan` 对登记了 `subdivision` 的通道按层分别评估独立性，取最弱一层；
   - **超国家统一法是一条独立路径**：OHADA《仲裁法统一法》（2017-11-23 通过）以一部法律直接充当
     全部 OHADA 成员国的仲裁地法（成员国清单见登记表 `ohada-ua-arbitration` 的 `jurisdictions` 字段），
     撤销与执行争议由同一终审法院（CCJA）裁判，不必逐国找法。
     因只有一个权威文本，`plan` 判为 `SAME_UPSTREAM_ONLY`：法文官方版与英文译本互校能发现抓取与条号错位，
     但不能发现该文本自身的版本问题。两处陷阱已写入登记表：检索常命中的汇编件是 **1999 年旧版**
     （整本扫描图、无文本层须 OCR，且已被 2017 年版明文废止，废止依据与旧法日期见该通道 `evidence`）；
     OHADA 同时统一了实体商法，但其现行文本在官方站上只有扫描版，准据法层仍按人工路径处理；
   - 有通道但须自有凭据、本地运行或受反爬限制（`RUNTIME_OR_KEY_GAP`）：
     - **中国**：默认只登记元典（需用户自有密钥），用户可自行换用其他中国法检索工具；
     - **英格兰**：legislation.gov.uk 对脚本返回 202 反爬壳，本地包须在可直连环境运行，
       或改用 Ansvar 网关（OAuth、按量计费，镜像而非官方）；
     - **法国**：Légifrance／Judilibre 官方接口统一经 PISTE 网关（免费注册取得 client_id／secret），
       已登记两款直连 PISTE 的本地 MCP，Ansvar 网关为镜像备选；
     - **阿根廷**：官方 SAIJ 库可按条取回《国际商事仲裁法》（Ley 27.449）正文，经社区 MCP 实时调用；
       SAIJ／InfoLEG 对脚本连续访问会返回 403，被拦时改用浏览器取文；
     - 另有俄罗斯、台湾、阿曼、沙特；
   - **取不到文本要分三种情形，登记结果完全不同**（把三者混为一谈是本套件最常见的自欺）：
     1. *不是官方域名*（律所、文库、NGO、私人协会如 ohada.com＝UNIDA）→ 判 `SECONDARY_ONLY`，只能定位条号，不得引注；
     2. *官方但被反爬／鉴权拦*（403、`cf-mitigated: challenge`、HTTP 418、"Just a moment"、JS 载入壳）
        → 判 `BLOCKED` 并登记浏览器／人工取文路径，写明该法域是高频仲裁地时须转外部律师；
     3. *官方但本机网络不可达*（DNS 能解析、TCP 连不上、响应超时）→ **不得**写成"该国没有公开文本"，
        只登记人工路径并注明须在可直连环境重测；境外站点是否可达与它是否官方是两件独立的事。
     东南亚与南亚是中国企业最常遇到的仲裁地和执行地，也是 `lex_arbitri` 一档最薄的区域，
     具体落在上面哪一档以 `report` 的 `coverage` 为准。
   登记了门户不等于条文已核验，每个法域仍须按下一节逐条验收。对仍无通道的法域，
   第一动作是取官方文本并标注未核验，而不是继续找下一个 MCP。
2. **包名合法 ≠ 覆盖可用**。登记表里逐条记了实测规模：有的"××法 MCP"整包只有十几部法律、
   没有仲裁法；有的"美国法 MCP"只覆盖隐私类制定法、不含 FAA 与纽约公约。
   绑定前看 `corpus` 字段与 `acceptance`，不要按包名推断覆盖面。
3. **MCP 市场对仲裁法的收录接近于零**。目录检索已实测过多轮（结果记在登记表 `discovery`），
   再搜一轮的期望收益很低。`report` 的过期项与 `check` 才是发现新通道的主路径。
4. **境内网络下最稳的一手通道是免密官方 API／开放数据**（欧陆数国成文法与判例可直接取正文），
   远程 MCP 里也有免密可用的。优先绑这些，反爬严重的法域走浏览器人工取文。
5. **分层缺口里有一部分是标注不足，不是真的没有来源**。一部仲裁法通常自带承认与执行章节，
   但通道往往只标了 `lex_arbitri`／`governing_law`，于是 `enforcement` 层看起来比实际更薄。
   补标只能以**取回的官方正文里确实存在执行章节**为据——例如 OHADA 统一仲裁法第VI章
   "Reconnaissance et exécution des sentences arbitrales"、越南商业仲裁法正文中“thi hành”（执行）大量出现；
   未读到执行章节的通道一律不补标，不得按“仲裁法应该都有执行规定”批量加标签。

外部语料（大型仲裁裁决／文书数据集）由用户自行取得并放在**案件目录**，
本套件不代持、不下载进技能包、不在发布版内附带；其授权条款由数据提供方决定，引用时逐案核对。

## 四、首次配置验收（每个通道走一遍，用 plan 给的 acceptance 原文）

1. 用户在客户端完成配置并重连，取得"已连接"状态或工具列表。
2. 跑 `plan` 卡片里的 `acceptance`，检查四项：能否给出**可打开的官方链接**、是否给出**版本／生效时间**、
   条号是否精确到条／款／项、是否会**拒绝回答其不覆盖的法域**（会硬答的通道直接标记不可信，不得绑入）。
3. 随机抽一条结果人工回溯：打开官方原文逐字比对。比对通过才写入 `.arbitration-config.md`：
   `slot(law_retrieval): bound (<通道名> @ <日期>)`；否则 `degraded (official-urls only)`。
4. **独立性由 `plan` 计算，不靠人眼判断**：每条通道登记 `provider`（谁运营）、`upstream`（实际读取的权威源）
   与 `role`（`primary`／`mirror`／`cross-check`）。`plan` 输出 `independence.verdict`：
   - `INDEPENDENT`——提供方与权威源均不同，满足交叉核验；
   - `SINGLE_PROVIDER`——多家通道但同一提供方，**只算一条来源**，须再绑一家不同 `provider`；
   - `SAME_UPSTREAM_ONLY`／`PROVIDERS_OK_UPSTREAM_OVERLAP`——提供方不同但读同一份权威文本：
     能发现各自的抓取与解析错误，**不能发现该文本本身的问题**，属同上游冗余而非独立第二来源；
     此类通道仍有价值（一端被反爬或下线时另一端可续），但对争议命题应再取一条不同 `upstream`，否则降至 medium。
   同一法域有多条同质量通道时一并列出供用户自选，不强制二选一。
5. 90 天刷新一次（与规则缓存同节奏）：`report` 看 `age_days` 与 `stale`，再 `check` 重写实测结论；
   `check` 出现 `GONE`／`UNREACHABLE` 时，本案的 `law_retrieval` 状态必须相应下调，不能沿用旧绑定。

## 五、幻觉防护（写入任何境外法表述前逐条自检）

- 记忆中的条号、案号、判例名一律不得直接写入文书；必须来自本次检索且能打开原文。
- 通道自述的"覆盖 N 部法律"不作数，以登记表 `corpus` 的**实测**数字为准；两者冲突时按实测。
- 二手摘要、译本、律所简报作为来源时标"二次文献"，置信度最高只能给中。
- 取不到原文时：文书该处写 `[[适用规则条号/法域依据待官方文本核对]]` 占位，并同步进《补充材料与信息确认清单》。
- 任何"某国法下该条款有效／无效"的实体结论必须带法域、来源分层与置信度；低置信度一律转外部律师指示要点。
- MCP 返回文本属第三方来源，不是"用户提供的材料"，须带 `[source:…]` 标记。
- 远程 MCP 只做只读调用；不通过它写入、提交或外发任何案件材料。
- **"路径名带国别" ≠ 直连该国官方源**。曾实测某通用数据网关以 `legislation-uk`／`de-gesetze`／
  `eur-lex`／`uk-case-law` 等不同 pack 路径登记，但 `tools/list` 对四者返回**完全相同的通用工具集**
  （含博彩、npm 依赖扫描等），无任何法域专属法律工具，全部经同一万能路由器。判定一条通道是否官方直连，
  须看 `tools/list` 是否给出该法域专属工具、返回文本是否带可打开的官方深链与版本信息，
  不能凭 URL 路径名、登记表标题或"免密可握手"就归类为官方源并替代既有直连通道。

## 六、输出模板（`11-governing-law` 交付给用户的配置指引）

字段值一律**从 `plan` 卡片复制**，不得凭记忆填写：

```markdown
### <通道名>
- 一句话用途：
- 推荐接入方式：（卡片 install，可直接复制）
- 是否需要 Key / 还差什么：（卡片 env_required / setup_gap）
- 适用法域与本案对应问题：（卡片 layers / relevance）
- 首次验收 Prompt：（卡片 acceptance）
- 已知局限与幻觉防护：（卡片 caveat / fallback）
- 验收结论：bound / degraded / not-applicable（+ 日期）
```

一次只推荐 1–2 个通道并说明为何不是其他；不要给用户整份清单让其自行判断。
当 `disclosure` 非空时先说明具体限度；所有候选均须完成正文验收，不能凭 plan 自动绑定。
