# 跨境承认与执行

先给一页决策：目前能做什么、最近不可回避的期限或核验任务、最多 3 项待用户决定事项。区分“文书能否承认”“可否采取执行措施”“哪些债务人资产可处置”“回款是否实现”，不得合写成“可全球执行”。不预测法院结果、胜诉率或回收概率，不代拟境外法院申请书／表格，不保证资产调查结果。

## 一、按目标选 profile，不把全部材料叠加

| profile | 使用时点与最小输入 | 交付与检查阶段 |
|---|---|---|
| `forecast` | 裁决前；已知协议、拟请求／救济、程序节点、债务人及可能资产信息；不要求已有裁决 | 十二项预判＋当前可修补动作；stage forecast |
| `plan` | 裁决后；已得裁决和程序信息、回款目标、资产线索或明确未知、预算约束 | 有条件执行计划、目标及调查任务；stage plan |
| `asset` | 债务人身份、已有合法线索或未知、调查范围 | 调查与保全任务清单；stage plan；裁决前可用 forecast |
| `immunity` | 国家联系及主体资料、拟执行资产性质、已知豁免条款 | 管辖／执行两条核查线；stage plan 或 forecast |
| `insolvency` | 已知破产事件、债权、目标法域与其他程序 | 中止范围、申报及协调核查；stage plan 或 forecast |
| `board` | 当前方案、预算及待授权选择；允许可靠记录中的未知 | 一页五节决策简报，明细外置；stage board |
| `counsel` | 目标法域或待定位范围、具体问题、最小事实、报价／预算授权与期望交付日 | 可报价的核验指示；stage plan，不以filing为前提 |

`filing` 是选定目标准备提交的核验阶段，不是第八个 profile。`board` 只在用户要管理层决策材料时生成，不是 plan、asset 或 counsel 的共同前置。轻任务只保留必要表格与情景，资料未知列缺口而不是逼用户填数。

```bash
python3 <suite>/scripts/route.py --gate 14-cross-border-enforcement --profile forecast --workdir <案件目录> --provided <案件目录>/case.json
```

`case.json` 登记已知、明确未知、核验任务、负责人及工作截止安排。已有裁决不是 forecast 材料门；法律期限、法院及代理要求的未知可以正是 counsel 的问题。旧案件缺矩阵不阻止独立执行研究，切勿为过门伪造事实。材料不足时保留可做部分及受控草案，不能提交未核验申请。

## 二、底账与十二项预判

`案件档案/enforcement-plan.yaml` 使用 `schema: 1`，可独立存在。新案件矩阵为 `schema: 2`；如有，复用 F-/E-/CL-/DF-/R-/EV-/A- 与 T-，把 `enforcement.forecast_ref / targets / awards` 作为引用，不复制两套金额与事实。无案件矩阵时在执行底账记录本地事实、文书、证据与来源，不编造不存在的案件锚点。

裁决前允许 `awards` 为空，用拟请求、预期裁决形式与程序记录说明评估基础。裁决后逐份记 AW- 类型、作出／转交／收到日、seat、机构／规则、主文义务、币种、本金、利息、费用、送达证据、终局性、更正／补充、撤销及执行状态；可否独立挑战交 10 核验，不把每份中间文书都当可执行裁决。

`amount_by_relief` 完整映射本裁决的 money／costs 救济；money 分配合计等于 `principal`，costs 分配合计等于 `costs` 分类金额之和，均以该记录的 `currency` 计，不混入利息。费用单独裁决不虚构本金；多币种主文按原裁决与币种拆记并标明同一文书来源，不自动折算。仅有一个 money 且无 costs 救济时可直接用本金映射。

|---|---|---|

## 三、先识别文书性质，再查路线

按需读 `references/enforcement-jurisdictions.md`，以条约保存机关、现行实施法、法院及其他官方原文核验范围、保留、地域与时间适用。保留准确条文、案例引注、反向权威和后续处理。所有具体命题带 `[source:<id> | <版本> | <页条段> | <已核验URL> | 校验 <日期>]`，不预置国别结论、期限或成功率。

| 文书／路径 | 分流及核验 |
|---|---|
| 商事仲裁裁决／纽约公约 | 先判定外国／非内国等适用范围、保留与实施法；查第 III／IV／V／VI／VII 条相关问题。V(1) 通常由抗辩方证明，V(2) 可仲裁性及公共政策可由法院依职权审查；不要说全部事由均只能由败诉方举证 |
| 公约不适用或其他可用机制 | 分别查国内法、更有利规则、双边条约、区域／区际安排；无可确认路线时保留调查与独立担保／保险问题，不假称不能执行或已找到替代 |
| ICSID／投资条约信号 | 只识别文书、制度与转交材料；转投资争端专业律师，不进入商事执行 filing，不按纽约公约处理；也不能因投资条约就推定为ICSID裁决 |
| 外国法院判决 | 另核判决性质、管辖基础、条约／国内法、终局性与拒绝事由；不能通过先取得判决“洗掉”仲裁执行障碍 |
| 调解和解协议 | 查《新加坡调解公约》或当地制度适用范围、保留、排除、证据和形式；普通和解不自动是调解公约文书，也不自动是裁决 |
| 破产债权、担保、保险、重新起诉 | 各有独立权利基础、时效、既判／仲裁协议、申报及管辖问题，不是绕过拒绝执行的魔法路线 |

中国 inbound 需先分外国、港澳台区际及其他裁决，核验当前法院管辖、期限、报核及文件要求；中国 outbound 按每个目标地核验。不能用中国法院规则替代境外程序。

## 四、执行目标、资产及文件链

目标 T- 至少登记法域、候选资产类型／位置／来源、债务人、产权人、责任依据、权属置信度；资产价值与变现能力、负担和转移风险均需证据。**关联公司账户不是主债务人的资产**；持有子公司股权也不等于拥有子公司账户。涉及担保、共同责任、追索转移财产或揭开面纱时分别核验独立依据、程序及范围。

无具体资产可以登记调查候选地与任务，但不能列为已核实可执行资产或虚增回款。plan 可保留线索性目标与阻塞；filing 所选目标须满足当地承认／措施程序所需连接点、主体及权属依据。只申请承认可能不要求特定资产，须有当地法确认；拟查封具体资产必须有相应财产与责任基础。

每个目标按以下块维护：

- 文书类型、适用路线、条约／保留／实施法及来源；非公约路线的独立适用条件。
- 程序、法院及级别／地域连接点、送达、本地代理要求、已聘律师及权限。
- 期限：名称、期间、起算事件与证据、届满日、可延展性、计算口径、核验人和来源。未核验 due 写 unknown；不能编天数。
- 文件：裁决与更正／补充件、协议及并入文件、程序送达证据、主体／授权、当地申请、财产线索、费用／担保。逐项记录已有、待办、需翻译／认证、核验依据与完成证据。
- 译本、公证、认证、Apostille 或电子方式按具体文件、缔约适用与法院要求核查，不一律要求叠加办理，也不承诺普通译本等同认证译本。
- 豁免、破产、制裁、公共政策、平行程序、保全、预算、时间线、负责人及 OQ 缺口。

合法调查限公司、不动产、船舶／航空器、IP、法院／破产登记、公开采购、客户合法持有资料、合规征信与当地律师查询。覆盖账户、应收账款、存货、设备、不动产、股权、船舶、航空器、IP、许可／现金流；其他资产依当地法与可识别性处理。不得黑客、冒充、社工、骚扰、非法购买个人或银行数据，不绕过访问控制。

保全逐地核验庭／法院权限、单方或通知、担保、比例、资产位置、后续启动期限、第三人异议与错误保全责任。资产变动迹象只记证据和合法救济，不把异常交易直接定性为欺诈，也不通过违法取证找资产。

## 五、专项与平行程序

**豁免**：先辨国家、机关、国企、主权基金与独立法人及实际资产所有人。国有不自动享有主权豁免；仲裁协议不当然放弃执行豁免。分别核验管辖豁免与执行豁免、法定例外、放弃措辞及有效权限、特定资产用途和特殊保护。中国《外国国家豁免法》适用于中国法院场景；其域外对应规则另查，不能混用。商业用途也非对任何资产自动可扣押的保证。

**破产**：区分申请、受理／启动、命令及境外承认；核查中止的时间、地域、主体、财产、例外／许可、申报期限、顺位、担保、抵销和撤销权。破产申请不当然开启全球中止，集团破产不自动合并财产。当地中止确认后调整动作并保护申报窗口，不自动“加速到期担保优先”而略过破产限制。

**平行程序**：记录撤销、承认、执行、保全、破产、和解与支付。纽约公约第 VI 条延期审查／担保、既判与禁止矛盾陈述等按法院确认。未异议不当然适合转去执行地；撤销成功不当然终结全球执行。统一事实、已收款、担保及和解信息，通知协调律师，不能跨国重复受偿。

## 六、回款、预算、时间与和解

1. 按 AW-/R- 建同一回款底账：裁决余额、本金、利息、费用、付款币种／日期／凭证、实际抵减口径、已收款与已处置财产。冻结、担保或判决不等于实收；不同币种抵减须查适用汇率及法律口径，不能简单相减。
2. 预算按目标与币种列法院费、律师费、翻译认证、专家／执行服务、差旅、税费及预备费，区分已发生、承诺、待批准。担保本金／保证金占用与实际费用分开。**无汇率与日期／来源时不得跨币种合计**；有汇率的管理折算另列，不覆盖原币金额。不明成本写 unknown，不填 0。
3. 时间线分准备、立案、送达、听证、裁定、救济、变现，写依赖及估算依据，不许以流程表承诺完成时间。场景以明确资产、折扣、成本假设计算现金影响，无依据不编回收区间；不附概率。
4. board 仅列决策、现金影响、关键期限、Top 3 风险、建议与授权五节；内容以一页为目标，渲染后人工检查页数与可读性，细表放附录，不能承诺自动 Word 一页校验。
5. 和解主体、庭权和合意裁决转 10；14 核验当地履行、担保、付款合规、既有裁决保留与释放条件。不得为取得新合意裁决先释放现有权利；所有回款及时抵减并协调各地程序。

## 七、核验阶段与对外交付

```bash
# 每个 profile 各自 init 一份主表：不带 --profile 只生成 plan 形状的文件，
# 拿它跑 forecast／board 阶段会因缺该 profile 的必填段而被 schema 拒绝
python3 <suite>/scripts/enforcement_matrix.py init --case <代号> --profile forecast --out <案件档案/enforcement-forecast.yaml>
python3 <suite>/scripts/enforcement_matrix.py init --case <代号> --profile plan     --out <案件档案/enforcement-plan.yaml>
python3 <suite>/scripts/enforcement_matrix.py init --case <代号> --profile board    --out <案件档案/enforcement-board.yaml>

python3 <suite>/scripts/enforcement_matrix.py check --in <案件档案/enforcement-forecast.yaml> --stage forecast --profile forecast --json
python3 <suite>/scripts/enforcement_matrix.py check --in <案件档案/enforcement-plan.yaml> --stage plan --profile plan --json
python3 <suite>/scripts/enforcement_matrix.py check --in <案件档案/enforcement-plan.yaml> --stage filing --profile plan --json
python3 <suite>/scripts/enforcement_matrix.py check --in <案件档案/enforcement-board.yaml> --stage board --profile board --json
python3 <suite>/scripts/enforcement_matrix.py render --in <案件档案/enforcement-plan.yaml> --out <交付目录/14-跨境执行方案.md>
python3 <suite>/scripts/enforcement_matrix.py summary --in <案件档案/enforcement-plan.yaml>
```

按本轮 profile 选择而非一次跑齐。矩阵必须明确本轮拟提交的目标及申请范围；未选择目标不能声称 filing-ready。

矩阵类脚本（`enforcement_matrix.py`／`case_matrix.py`／`clause_audit.py`）的退出码：

| 退出码 | 含义 | 处置 |
|---|---|---|
| 0 | 通过或仅带已登记缺口（`REGISTERED_GAP`） | 可继续；缺口仍须按 `pending` 追办，不得表述为已核验 |
| 2 | 必填内容未满足，或文件形状与 profile 不符 | **先读 `errors[].code` 再决定动作**：`BOARD_SECTION`／`FORECAST_ITEMS` 等指向具体段落缺失，属内容未填，填该项；`TYPE`＋路径表明是文件形状与该 profile 不匹配，才按上表用对应 `--profile` 重新 init。不得为凑过闸门而改结构字段，也不得把内容缺项当作 profile 错误重初始化 |
| 3 | 材料闸门未过（占位、台账缺项、冲突） | 出补充材料清单，本轮不交付 |
| 4 | 请求的组合本身不支持（未知 profile、不在迁移路径上的 `--from/--to`） | 属用法错误，不是内容不合格：改用受支持的 profile／阶段，不得当作核验失败 |

| stage | 允许与阻断 |
|---|---|
| forecast | 不要求裁决、法院文件齐套或董事会五节；要求评估基础、十二项状态及关键缺口／当前动作。缺口可保留，不能虚构执行结论 |
| plan | 允许法律／事实 unknown 和线索性目标，同时登记影响、owner、due及阻塞节点；可交内部计划、合法调查和向律师求核验的指示；不等于准许提交 |
| filing | 仅就明确选定目标核验：文书与路线可用、期限及起算证据、法院／程序连接点、申请所需文件链、代理／签署授权、资产与责任依据（按请求范围）、专项中止／豁免／制裁处理及必要许可。实质核验与证据未完成即阻断；不能用“已核验”布尔值或结构通过替代当地律师确认 |
| board | 要求五节决策、分币种现金／预算、最近期限或核验任务、风险及授权，未知可披露但不能充当已知回款；不代替filing，页数人工核对 |

counsel 是研究委托而不是执行申请：明确问题、法域／定位任务、最小事实、所需引用层级、报价或预算上限、交付日及披露授权即可发核验请求。是否受理、期限、法院、文件和代理都可作为待答问题。外发前完成适当冲突核查及保密安排，不整份发送内部攻击线、谈判底线或未经授权材料；回件需独立复核来源与适用性。

所有内部模板 `pair: false`。对外律师指示需 `.docx`，非中文时另配《中文审阅说明》（中文指示函不另出），不因内部计划有未知就禁止发送研究问题。对外法院文件由当地律师按当地规则制作，提交前再过 filing 与用户授权。

案件段落锚点使用 `#! 锚点：F-001 / E-CL01-01 / CL-01 / DF-01 / R-01 / EV-001 / A-01`，只用已存在且有关的 ID；独立执行件不伪造 case 引用，T-/AW- 在表内作索引。执行 `verify_suite.py --workdir <案件目录> --mode draft|submission`，独立执行件只要求适用执行矩阵，不强迫补旧 case-matrix。校验器只检查记录与结构，不证明法律结论正确。
