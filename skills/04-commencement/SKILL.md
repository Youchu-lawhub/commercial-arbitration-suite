# 启动程序与仲裁申请书

申请书同时干三件事：跨过机构的形式审查闸门、锁定程序起算点以对抗时效、给仲裁庭留下第一版案情。它不是实体书状，写太满会提前暴露策略并压缩己方修正空间；写太简会被补正通知吃掉时限。

## 一、入口闸门

材料与入口闸门以 `suite.yaml` 本子技能条目为准（铁律 3、4）；已明确的事实直接登记，不重复索取。
已读取材料登记到案件根 `case.json`（`rulesuite-case/1`，台账口径见 `references/practical-workflow.md`）。

```bash
python3 <suite>/scripts/route.py --gate 04-commencement --workdir <案件目录> --provided <案件目录>/case.json
```

未通过时只追问影响本轮结论的缺项；可先出未完成标记的框架，不虚构事实（铁律 3）。

## 二、起草动作

- 先读取当前 `案件档案/case-matrix.yaml`（schema 2）及 `references/case-construction.md`，从 CL → E → F → EV/缺口 → R → A 构建本轮申请；新材料先回写底账，不照抄旧书状作为事实源。
- 记稿声明 `workflow: 04-commencement`、`matrix: case`；本技能在 `suite.yaml` 无 profile，不添加虚构 profile。`case` 仅为稳定案件代号。
- 事实、归摄、救济段附近写内部追溯行，如 `#! 锚点：F-001 / E-CL01-01 / EV-001 / R-01 / A-01`；仅使用矩阵真实编号，不相关组省略，不用 `[[F]]` 或 `[[F-001]]`。EV 与对外附件号分别映射，`#!` 不进入 Word。
- 起草前及提交前按案件构建参考留存 AT/PM 对抗审查，覆盖最强反驳、不利材料、回应与残余风险；同一人自审标 `self_review`，不称独立审查。
- 金钱项才核金额/币种及实际主张的利息依据；非金钱项写对象、行为、范围、期限及执行障碍，不强加利息。实质未知登记 OQ，受控草案的 Q 占位另入 `pending.json`。
- 交 12 前对当前矩阵执行 `case_matrix.py anchors --in <矩阵路径> --draft <文书.md>` 及 `check --in <矩阵路径> --stage submission`；草案用 draft 阶段，阻断只限受影响任务。

1. **先把本案的"必载项清单"取回手**（铁律 1、2）：
   ```bash
   python3 <suite>/scripts/fetch_official.py applicable --inst <机构> --commencement <拟提交日>
   python3 <suite>/scripts/fetch_official.py fetch <rules-source-id> --to-md
   python3 <suite>/scripts/fetch_official.py lookup <rules-source-id> --pattern "Request for Arbitration"
   ```
   必载项、副本份数、答辩期、起算点、费用表条号一律在该版本文本中逐字命中后再写；机构立案页与 practice note 属另一来源，与规则本文本分别标记。
2. **六项必载逐项落位**，每项都要能在文书里指出位置：

   | 必载内容 | 缺项如何拖慢程序 |
   |---|---|
   | 当事人识别与可用的送达地址、电话、邮箱 | 机构通知送不出，案件起算日被推后，时效风险落到我方 |
   | 争议性质与发生情形 | 机构无法判定主管与程序类型，反复补正 |
   | 救济请求及可量化金额 | 费用按保守档核定，预缴通知来回调整 |
   | 仲裁协议文本（逐字引述并指明合同与条款号） | 形式审查与 prima facie 管辖判断被卡，甚至被转交争议程序 |
   | 组庭提名及相关信息（人数、指定方式、候选人） | 组庭延后，机构径行代指而丧失提名机会 |
   | 约定或待定的仲裁地、语言、准据法 | 后续程序令阶段重开争点，被动接受默认规则 |
3. **选变体**（判据：金额与复杂度／是否需要紧急措施／是否要以立案文书施加和解压力）：

   | 变体 | 何时用 | 注意 |
   |---|---|---|
   | 简洁版 | 金额中等、事实清楚、无紧迫行为 | 事实与请求完整即可，不展开实体论辩 |
   | 合并紧急救济版 | 对方正在转移资产、兑付保函、销毁证据或抢占许可 | 紧迫部分独立成节、控制在数页内，措施措辞可直接执行（对象、行为、期限、违反后果），只对被申请人设义务而不请求命令第三人，并保留向法院申请保全的权利；是否设有紧急仲裁员机制及其适用条件须先现查 |
   | 详尽版（含目录） | 高金额、多合同、技术争点复杂，或需以立案文书施压 | 主文前置到摘要之后，实体深度止于"说明争议"而非"完成举证"；页数与机构立案惯例和后续程序令限制对齐 |
4. **写法硬规则**：首页要素栏（仲裁地／规则与版本年份／当事人与代理人国籍／准据法／标的）逐项填写，未定项使用已登记的 `[[Q编号:待确认事项]]` 草案占位，不将待定状态伪装成定稿；事实段按"合同—履行—违约—损害"四拍编号成段，只写事实；合同准据法与仲裁协议准据法分节陈述；管辖权一节逐字引述条款并给出机构管辖依据条号。**保留补充修改权利的必写句不能漏**：英文文书写 "Claimant reserves the right to supplement, amplify or amend its claims, evidence and arguments."，中文文书写"申请人保留就其仲裁请求、证据材料及事实与理由进行补充、修改和进一步陈述的权利。"，无此句后期扩表易被指为程序突袭。条款存在病理（机构表述冲突、前置协商条件、多合同不一致）时主动点出并给出我方论证，比被对方提出后再解释更有利（铁律 7：同时写出对方最可能的解读与仲裁庭关注点）。
5. **金额量化与费用档级**：多数机构的行政管理费与仲裁员报酬按争议金额分档，条号与费率表现查（费用表多为网站公布值，须记取值日）。做成请求项台账：请求项／币种／金额／计算式／凭证号／附件号。利息写满四要素（基数、利率或口径、起算日、单利或复利直至实际支付日），并按案由确定分段单位：货物买卖、运费、服务费按票或按笔；航运按航次／租期／提单；借款、租赁按提款与还款；EPC 按付款证书／里程碑；合资、股权、M&A 按单笔本金或价款分期；能源、矿业、长期供货按交付批次或合同期；许可按特许权期间；投资条约按估值基准日。非金钱请求不计利息；违约金／罚息如属独立请求，单列并另核其性质与可调减性。注意金额口径：反请求与抵销是否并入计算、选择性请求按主请求计、汇率取值日、连带责任不重复计——按适用规则现查确定，并预判"对方若提出反请求会把案件推入哪一档、是否触发或脱离简易程序"。
6. **仲裁员提名**：先取得被提名人本人同意，再索取其简历与联系方式（部分机构要求提名时一并提交简历与同意，条号现查），文书中列全名、国籍、住所、电话、邮箱与资质说明；同意与联系方式用于机构向其发披露函，不要把未经同意的人写进申请书——事后撤回可能影响提名与组庭安排，具体后果按规则和机构决定判断。三人庭要写清主席产生机制，可另就首席提出客观标准（语言、行业、法域经验、可用性），不得写倾向性表述。
7. **送达方案**：依适用规则判定是机构转送还是申请人自行向被申请人送达并向机构交副本；自行送达时必须留送达凭证，因为部分规则把起算点放在对方收到日而非发出日。核对副本份数（按当事人、仲裁员、机构各份）、提交渠道（线上立案系统／邮件／纸质）与格式要求（可检索 PDF、单一文件、命名规则、附件合订），逐条列成 `04-立案材料包.md` 的检查表；对方邮箱用其合同指定或曾使用的通知地址并附备选方式。
8. **立案费用测算**：按现查费率表算行政费与仲裁员报酬预缴，登记缴费凭证号与到账日；部分机构未附费用即视为未送达或直接关闭档案，缴费动作要排在提交之前而非之后。同时测算己方律师费与听证成本，与快速程序／普通程序分档一并给出对比，供管理层决策。
9. **证据与证人边界**：附件只放基础文件（合同与附录、仲裁条款、催告与往来函件、账目与付款记录），按 C-1、C-2 连续编号且正文逐段引用，避免"有证据无锚点"。**证人陈述不进申请书**，留到实体书状阶段；专家亦然。
10. **签署与授权**：授权签字人姓名、职务、签署地与日期齐备；代理权限文件（PoA）须覆盖提名仲裁员、签署文书、提出与回应请求、和解、收款、指定证人与专家、申请临时措施等具体权能，有效期覆盖到裁决签署与费用结算（宜写"直至程序包括执行终结"），并按机构与法域要求处理公证、认证与译本——该形式要求属当地法判断，转 `11-governing-law` 出结论，本技能只提示触发。
11. **交付前自查**：主文与请求台账一致；每个条号都有来源标记；每个日期都有依据文件；当事人全称与案件档案一致；无未核实的主体信息（铁律 3）；预判对方在管辖、金额口径与送达上的三个攻击点并写入说明。

## 四、常见错误

- 当事人法定全称、法律形式或注册地写错，关联公司混用 → 执行阶段被指主体不适格。
- 缺电话／邮箱／收件地址，或漏掉向对方的送达与凭证 → 程序起点被推后。
- 金额未量化或未给计算口径，费用档级与预缴通知反复调整。
- 引述的条款版本与实际签署合同不一致（附了旧模板条款）。
- 提名仲裁员未取得事先同意、未附简历与联系方式 → 可能引发补正、替换或指定程序，不能预判必然推翻组庭。
- 请求救济超出条款范围，或把只能由法院作出的措施请求仲裁庭命令第三人。
- 把证人陈述与全部证据塞进申请书，实体论辩写满，丧失后续修正空间。
- 漏写保留补充修改权利句；或份数、格式、缴费时点不合该版本要求而被补正。
- 凭记忆写条号、份数与天数 → 违反铁律 1、2；出英文稿却不配中文审阅说明 → 违反铁律 5（中文文书不需配，也不得为凑配对硬写一份）。

## 六、每次随附立案申请指引

每次输出仲裁申请材料，均按 `assets/templates/04-立案申请指引.md` 另交《立案申请指引》，包含草案和重写稿；变更稿须刷新受影响步骤。指引不能被 `case.json` 材料台账或中文审阅说明替代；作为内部操作指南不再为其递归生成审阅说明。按 `references/filing-and-company-research.md` 在起草期间核查官方立案入口、公开操作手册、送达规定、邮寄要求与费用页。浏览器可用且获宿主允许时，以只读方式检查入口和公开操作页面；无浏览器或登录后步骤不可见时明确标记“未实测／需登录确认”，不虚构按钮或字段，不模拟提交。纸质邮寄并非默认必需：给出本案是否需要邮寄及依据；需要时逐项列收件人、部门、完整地址、邮编、联系电话、份数、原件/复印件、签署、寄出时点和凭证，未确认不得编造。

机构命名与启动文书标题以本案适用版本的官方文本为准；不要机械保留通用 Request 标题，也不要在未取文时断言某版本使用何种文书名称。程序轨道与任命机制须先核验，不能仅凭金额就承诺任命无效或必被推翻。

本轮材料预填、跨阶段 gate_ids、显式 pending 草案、缓存导入、利息与程序轨道工具按 `references/practical-workflow.md` 执行；已登记待确认草案走 DRAFT_OK 交付审阅件，提交态仍须清除占位并通过 strict。该工作流取代“所有缺项一律禁止出草案”的旧说法。

《立案申请指引》默认作为独立 Markdown 操作说明随包交付，放本轮交付目录；运行 verify 时必须传 --filing-guide。草案指引中的未决项同样纳入 pending 清单。需要 Word 指引时另渲染并单独检查，不把内部指南当正式申请书递归配对。

起草、重写或润色按 `references/legal-writing-workflow.md` 分轮处理任务与论证、事实叙事、语言和版面，并回查法律含义；不得仅以表面流畅代替论证或改动事实与请求。

配套中文审阅说明的义务只适用于**交机构或交对方的非中文正式文书**；本身即用中文提交的文书不配中文审阅说明，铁律 7 要求的对置检查、待确认项与来源标记一律落在矩阵 `adversarial_review`、`open_questions` 与 `authorities` 里，交付前的逐段核对可另出标 `pair: false` 的内部核对件。内部立案清单、办理指引或计算台账可在记稿 frontmatter 标 `pair: false`；渲染会登记，核验明确输出内部件豁免，仍检查来源、占位、结构和同步性。不得把对外文书的配对义务用该豁免顶掉。
