# 仲裁协议设计与体检

先回答“现在能做什么、最紧迫的后果是什么、需要用户决定哪几项”，再展开研究。不给机构或仲裁员背书，不把某地法律、机构、语言作为默认最优解。

## 一、选择本轮任务

| profile | 最小输入（已有信息不重复索取） | 首要交付 |
|---|---|---|
| `new-clause` | 交易结构、商业目标、已定约束、拟签署主体；资产未知可登记 | 设计方案与可供谈判的条款 |
| `review-clause` | 条款原文及版本、适用法约定、相关合同；其余缺口显式登记 | 十二维体检与修补优先级 |
| `post-dispute` | 条款、争议与通知时间线、当前程序；紧迫日期单列 | 管辖、立案、前置程序、保全与权利保留行动 |
| `negotiate` | 对方文本或我方方案、谈判空间、商业底线 | 理想／可接受／退出线及条件式让步 |
| `compare` | 比较对象或选择范围、目标与约束 | 仅比较实际可选项的影响面 |
| `portfolio` | 合同清单、版本、主体及关联关系 | 一致性矩阵、冲突热力表与重谈日历 |

识别 `light / standard / complex` 及商业姿态 `likely_claimant / likely_respondent / balanced / unknown`；未知姿态不静默写成 balanced。姿态只影响合法程序利益的取舍，不用于拖延或规避。涉及交易类型时按需读 `references/transaction-dispute-patterns.md`，不得将货物买卖或普通法要件套用到所有交易。

先给一页决策摘要，最多列 3 项需要用户决定的事项。已决定的机构、仲裁地、法律、语言不反复重选。明细、场景模拟、客户问答、多合同表、双语版本只按本轮需要展开；轻任务不要求三个场景、十问或双语齐套。完整体检在矩阵覆盖 D01–D12；不适用项写理由，未核验项写缺口，不靠增加文书数量证明完成。

```bash
python3 <suite>/scripts/route.py --gate 02-clause-diagnosis --profile review-clause --workdir <案件目录> --provided <案件目录>/case.json
```

`case.json` 与本案代号一致，提交态由 verify 按 workflow/profile 互校；Markdown 清单只是视图。未过材料门可整理已知事实、受控草案和定向补料清单，不能伪造定稿。用户明确“不知道资产在哪”等答案可以作为已回应的信息登记，同时列调查路径、负责人、核验截止安排；空白与推测不能替代回答。通用规则导航不要求建立虚构案件。

## 二、锁文本、规则及法律层次

1. 登记合同、附件、订单、担保、版本、签署日、页条号、来源与可得的哈希。邮件摘录或截图仅作暂定文本，列出与签署版比对任务；不要因此拒绝解释已知文字。
2. 先按条款的版本约定、启动事件与过渡条款确定适用规则，不机械使用最新版。机构示范条款与规则本文分列来源；新设计现取现行示范条款，旧案保留历史版本定位。

```bash
python3 <suite>/scripts/fetch_official.py applicable --inst <机构> --commencement <拟启动日或实际启动日>
python3 <suite>/scripts/fetch_official.py fetch <source-id> --to-md
python3 <suite>/scripts/fetch_official.py lookup <source-id> --pattern <关键词>
```

3. 区分合同准据法、仲裁协议准据法、仲裁地程序法与执行地法。未明选仲裁协议法律不当然无效；查适用冲突规则及默认机制。CISG 仅在交易及适用条件相关时筛查，不自动纳入或排除。
4. 规则、法律、条约、判例与示范条款的具体命题带 `[source:<id> | <版本> | <页条段定位> | <已核验URL> | 校验 <日期>]`。保留准确法律引注与反向权威；未读原文、版本或效力未确认的命题标待核验。境外法研究转 `11-governing-law`，全球检索用 `references/global-research-protocol.md`，亚洲卡只作区域入口。

## 三、十二维与横切检查

| ID | 维度 | 核查问题与默认机制 |
|---|---|---|
| D01 | 机制与商业目标 | 仲裁、法院或适当混合机制是否适配终局性／上诉、专业性、保密、成本、多合同及执行目标；已合法锁定的机制无需重选 |
| D02 | 机构、规则与版本 | 能否识别机构与真实合意，是否更名／笔误，规则是否匹配；临时仲裁的任命机关及补位机制是否可用 |
| D03 | 仲裁地 seat | 区分法律仲裁地、开庭地、机构所在地；缺省地如何确定，法院监督与临时措施是否适配；跨境机构管理不自动违法 |
| D04 | 仲裁员 | 人数、指定失败补位、多方公平、资格、国籍、独立公正；偶数人数触发当地法及规则核查，不直接判无效 |
| D05 | 语言与文本 | 约定或缺省决定权、翻译／口译负担、证据语言、双语准文本；未约语言不自动升为严重缺陷 |
| D06 | 准据法分层 | 四层法律及选择法路径；强制规则和相关统一法；未选法造成何种实际不确定性 |
| D07 | 范围与可仲裁性 | 合同、非合同、无效、终止、清算、法定及 IP 请求、禁令、排除事项；区分效力与具体请求是否覆盖 |
| D08 | 多合同、多方及非签署方 | 主从合同、框架订单、引用并入、转让、担保、追加／合并的合意与规则条件；集团关系不等于受条款约束 |
| D09 | 前置程序 | 通知、协商／调解期限、完成证据、紧急例外、时效和弃权；区分可受理性与管辖争点，按法域确认 |
| D10 | 临时措施 | 仲裁庭、紧急仲裁员、法院各自权限、可用性、通知、担保及跨境落地；核验机制自动适用、选择加入或排除方式 |
| D11 | 裁决权限、救济及费用 | 金钱／非金钱救济、币种、利息、费用、抵销、责任限制；区分条款沉默与法定／规则授权，不为保险过度起草 |
| D12 | 执行、主体及合规 | 潜在资产、文书与条约路线、形式与授权、公共政策、国家／国企、破产、制裁；未知资产不等于无效或可执行 |

横切 X 表：签署／授权／形式、通知与送达、保密与合法披露、引用并入、可分性、反腐败／出口管制／数据、保险／担保／信用增强。逐项链接有关 D 维度，不另创总分。

### 判断必须分三轴

每维分别写**协议效力、程序可管理性、潜在裁决可执行性**的已知判断、适用法域与边界；“可管理”不等于“有效”，“不易执行”不等于“协议无效”。每维记录 `status / severity / confidence / finding / consequence / sources / missing_info`，把三轴判断写入 finding 与 consequence。

- `status`：`green / amber / red / unknown`，是当前核验结论，不是关键词命中颜色。
- `severity`：`green / amber / red / unknown`，表示后果轻重；Red 需说明重大后果、条件和应对路径。未查明时可记录条件性严重后果，但不得以此断言已无效。
- `confidence`：`high / medium / low`，依据文本、适用法与来源核验程度独立评定，不由颜色推导；high 也可对应已确认的重大问题。
- 未知是信息状态，不是危险等级。任何未核验项进入缺失信息框（问题、影响、来源缺口、owner、due）；不以 Unknown 冒充 Green，也不把所有 Unknown 升 Red。

病态形态只作候选问题：或裁或诉、多机构并列、名称错误、规则不匹配、只写“国际仲裁”、seat／语言缺失、范围不明、前置程序、引用并入与授权缺失。逐一查解释、默认、补位及修补路径后再定级；禁止扫描器直接下效力结论。

## 四、把检查变成行动

1. **执行反推**：及早问债务人及可能资产地，不把资产调查设为开始体检的绝对前提。资产未知时列假设及调查任务。结合 D12 与 `14-cross-border-enforcement` 判断承认、措施、处置三个层次；不要写“全球可执行”。非公约法域不自动否定条款，替代路线须独立核验文书性质与当地条件。
2. **模拟**：按交易与本轮问题选必要场景；轻任务可只走一个关键卡点或说明不需要。检查论坛、组庭、临时措施、文件、成本与执行依赖。时间／费用无依据写 unknown，不编区间、不预测胜诉或回收概率。
3. **多合同**：有相关文件才生成一致性矩阵。差异未必冲突，合并／追加也未必优于分案；区分未经同意的非签署方、独立担保人与主债务人。修补须说明谁应签署、对既有请求与时效的影响。
4. **方案及谈判**：在真实选择空间比较保留、局部修补、重构或其他机制；compare 至少有实际比较对象，只有一个合法可行选项时说明约束，不凑数。红线记录理想／可接受／退出线及批准人；不代用户决定。
5. **重写**：以官方示范条款或适合所选机制的已核验基线逐字段说明改动、理由、代价、补位与残留风险。常见独任／三人庭只是可选配置；快速程序与紧急仲裁员须查默认、门槛及排除规则，不一律要求 opt-in。保密须兼容监管、法院、审计、保险及适用资助披露。选择所需语言，只有双语时才作语义和准文本核对。
6. **中立性自检**：是否尊重既有合法约定与商业约束；是否有未经说明的机构／seat／法律／语言偏好；中国法与中国机构是否作为一等候选得到同等评价而非强塞；是否按相关法系核验；是否展示真正代价；未知是否透明。无需每案两机构、两法律、两语言，更不能用中国选项替换另一种默认偏科。
7. **争议期**：保留原条款证据，先保护通知、异议及保全窗口。补充协议不得无意释放已生权利；既有条款未被有效变更时，不按拟议重写条款启动。管辖与权利保留转 05，启动转 04。

## 五、矩阵、闸门与交付

`案件档案/clause-audit.yaml` 使用 `schema: 1`，可独立于案件矩阵存在；若已有 `case-matrix.yaml`（`schema: 2`），复用 F-/E-/CL-/DF-/R-/EV-/A-，不重复造事实。主键锚点为紧邻实质段落的 `#! 锚点：F-001 / E-CL01-01 / EV-001 / R-01 / A-01`，只能引用实际存在的 ID。条款库代号不占用 CL- 请求主键。

```bash
python3 <suite>/scripts/clause_audit.py init --case <代号> --out <案件档案/clause-audit.yaml>
python3 <suite>/scripts/clause_audit.py scan --file <条款.txt> --json
python3 <suite>/scripts/clause_audit.py compare --files <主合同.txt>,<附件.txt> --json
python3 <suite>/scripts/clause_audit.py check --in <案件档案/clause-audit.yaml> --stage draft --profile review-clause --json
python3 <suite>/scripts/clause_audit.py check --in <案件档案/clause-audit.yaml> --stage report --profile review-clause --json
python3 <suite>/scripts/clause_audit.py render --in <案件档案/clause-audit.yaml> --out <交付目录/02-条款诊断报告.md>
```

按实际任务替换 profile。`scan / compare` 只是抽取助手；`draft` 容许显式缺口；`report` 要求十二维、结论依据／明确未知、重大后果与措施、相关合同冲突及本 profile 的产物齐备，不按统一篇幅或场景／问答数量设门。未知不妨碍交付限定范围的体检报告，未核验的实质前提不能包装成可签署条款。脚本结构通过不替代律师判断与用户批准。

| 模板 | 用法 |
|---|---|
| `assets/templates/02-条款诊断报告.md` | 一页摘要＋按需展开的十二维明细，内部 `pair: false` |
| `assets/templates/02-条款重写与谈判红线.md` | 内部谈判方案；对外仅抽取批准条款，另配中文审阅说明 |
| `assets/templates/02-条款体检客户问答.md` | 业务语言、只答本轮所需问题，内部件 |
| `assets/templates/02-多合同条款一致性矩阵.md` | 合同关系与冲突，不重复建条款库 |
| `assets/templates/02-仲裁条款库.md` | 去敏化文本、适用条件、版本与复核登记，不是本轮必填 |

内部攻击线、退出线、未经批准的让步不得进入对外条款。对外文书选定语言、清理占位，交付 `.docx` 与《中文审阅说明》；内部件不强迫配对。最终使用 `verify_suite.py --workdir <案件目录> --mode draft|submission` 对应状态检查；独立条款任务不强制新建案件矩阵。
