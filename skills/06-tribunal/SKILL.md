# 组庭、披露与挑战

组庭是失权风险最集中的环节：提名权、异议权、挑战权各有独立期限，且互不救偿。涉外范围与规则版本按 `scripts/route.py --scope` 与 `00-cold-start` 已锁定结果执行（铁律 0、1）。

## 一、入口闸门

材料要求以 `suite.yaml` 的本子技能条目为唯一依据。已在会话中明确的事实直接登记，不重复索取。
对实际案件，先核对本案配置，再把已读取的材料逐项登记到案件根 `case.json`（`rulesuite-case/1`）；台账 `case` 与配置一致，Markdown 清单仅由台账生成供人阅读。

```bash
python3 <suite>/scripts/route.py --gate 06-tribunal --profile <文书类型> --workdir <案件目录> --provided <案件目录>/case.json
```

本子技能任务类型：`nomination`、`disclosure`、`challenge`。只选本轮需要的文书类型，不把其他类型的必填项合并进来。

未通过时，针对影响本轮结论的缺项提问；可先整理已知事实、检索路径与明确标为未完成的框架，不虚构事实，不交付未核验定稿。通用教学或规则导航问题不要求伪造案件配置。

## 二、动作

- 承接当前档案/已有矩阵中的条款、任命事件、送达及授权记录；仅核所选 profile，不为组庭重建全案。
- 候选人尚未确定时只列客观遴选标准与调查待办，不假想姓名、履历、国籍、语言、案件经验、可用性或利益冲突；实际候选人信息逐项保留来源与核验日。
- 提名、披露与挑战的期限分别按适用规则和实际触发事件确认；发出问询或请求暂停不等于获准停表，未获确认继续按原期限保权。
- 组庭/授权缺口交 01 更新记录，适用标准交 03/11 核验；挑战可能影响撤销或执行时分别交 10/14，不预断挑战或救济结果。

1. **解读条款的组庭指令**：把条款拆成五个变量——人数、我方指定权、对方指定权、主席/独任产生机制、任命机关（无机构管理时的兜底）。任一变量缺失即按**本案适用版本规则**的默认机制补足，条号现查、禁凭记忆：
   ```bash
   python3 <suite>/scripts/fetch_official.py lookup <规则版source_id> --pattern "number of arbitrators|appointment|president of the Tribunal" --max 12
   ```
   典型缺口：条款只写"三名仲裁员"而未写主席产生机制 → 依规则补足（双方各提名后由共同提名主席，或由机构/任命机关指定），并把补足结论与条号来源标记写入提名函，避免我方提名被以"条款约定不明"为由限缩。同时核机构保留的确认权（confirmation）与不行动代指机制：己方内部响应期限要按代指触发日倒排，写成日历项而不是"尽快"。
2. **建候选人客观要求清单**（全部可验证项，模板 `assets/templates/06-nomination-and-disclosure.md`）：仲裁工作语言能力、行业与技术背景、相关法域与程序经验、仲裁地/执行地国籍与中立性、当前可用性（在办案件数与时间表承诺）、时间承诺与案件管理理念、费用计算方式接受度（计时/从价、费率上限）、与当事人及代理人的既往接触（列案号、年份、角色、方别）。要求由用户材料与公开可查信息提供，本套件不代为认定主体信息（铁律 3）。
   纪律：提名函只写上述客观资质与可用性，**不得出现任何倾向性表述**（如"熟悉我方立场""能理解我方处境""与我方理念一致"）——此类文字一经披露即成为对方挑战与裁决撤销阶段攻击独立性的证据，也损害己方可信度。
3. **发提名/指定函**：必载项逐项填实，缺一项即可能被要求补正而吃掉期限——候选人全名（含拼写与头衔）、国籍、住址与通讯地址、电子邮箱、简历/学术与执业经历、候选人已出具的接受任命与独立公正声明及其披露声明、候选人可直接联系的确认、我方对人数与主席产生机制的意见、对适用规则版本的表态、抄送对方代理人与机构秘书处并注明"by email only"或份数要求。共同提名主席机制下另附己方可接受的主席画像（客观资质维度，不写具体推荐）。
4. **收到披露函后的处理**（当日启动，窗口极短）：
   - 登记收到时间——挑战/异议期限由此起算，条号现查。
   - 把披露事实**时间轴化**：关系起始日、终止日、是否仍存续、是否同一业务领域、是否与本案标的相连、涉及哪一办公室/哪一关联实体、收费安排。抽象的"无利益冲突"表态在挑战程序中几乎没有价值，只按具体事实与逐条切割评价。
   - 信息不足时发《披露问询函》（`assets/templates/13-procedural-letter.md`）：问题具体到时间段、是否同一事项、是否仍存续、与本案标的的关联，并明确以"**为有效行使异议权所必需**"（necessary for the exercise of my right of challenge）的措辞说明请求依据，同时请求指定期限内答复并确认该期间不计入我方异议期限。
   - 在规则期限内**书面**向机构/仲裁庭明确表态，只有两种写法：不提出异议并声明就此事实放弃异议；或提出异议并保留挑战权利（附条号 + 事实对应）。禁止"希望仲裁庭予以考虑""请仲裁庭自行裁量"之类模糊句式——模糊表态可能被认定为未在期限内提出异议而失权。内部备忘不等于书面表态。
5. **用软法定位，用规则定论**：以 IBA 利益冲突指引的情形分类作为**分类语言**（可抗辩推定/不可抗辩推定/不排除清单）快速定位事实类型：
   ```bash
   python3 <suite>/scripts/fetch_official.py lookup iba-conflicts-2024 --pattern "List|waivable|non-exploitable" --max 12
   ```
   结论必须落回**本案适用规则**的标准（独立公正义务、"可正当怀疑"式客观标准、披露义务、异议与挑战期限、决定机关），条号现查后带来源标记。软法不具拘束力，不得替代规则作为驳回或准许的依据。
6. **拟写挑战申请**（`assets/templates/06-challenge-application.md`）：骨架固定六段——① 依规则第 __ 条在期限内提出（条号与收件凭证）；② 事实陈述：按时间轴编号，只写可证事实，每条附证据锚点；③ 适用标准：客观第三人视角下是否产生"可正当怀疑"的偏见或利益，逐条切割对方将提出的减损事实（本人未参与该业务、无经济利益、与本案标的相关性、隔离措施）；④ 与规则标准和软法分类的对应；⑤ 请求与程序：请求决定机关在期限内决定、请求对方或仲裁员补充信息、请求挑战决定作出前暂停实体推进（仅在规则允许时）；⑥ 保留后续权利。举证责任在我方，不做"商业不便"包装：仲裁员背景不利、法律观点不合我方预期、对方提名仲裁员的国籍，均不构成独立性事由，混入会被驳回并削弱己方整体可信度。
7. **评估决定与救济空间**：现查决定机关（机构作出还是仲裁庭/其余成员作出）与决定的终局性，并写明后续路径与各自的严格期限——机构决定不可再诉时，剩余空间通常在裁决撤销或不予执行阶段的正当程序抗辩（转 `10-award-post`）。是否继续推进程序、是否同时向法院申请指定/回避，须先由 `11-governing-law` 输出该法域口径与置信度，再落笔（铁律 6）。
8. **核代理权限（授权委托书）**：以"要做的每一个程序动作"为轴逐项对照权限清单——订立/参与仲裁程序、指定与同意仲裁员、签署任务书、提出与回应请求与反请求、提交与撤回书状、和解、接受送达、收取款项、指定专家与证人、申请临时措施与担保费用、签署裁决相关文件。漏一项就可能在提名或签署任务书时被要求补正而失期限。期限式授权须留缓冲：到期日晚于裁决签署与费用结算的预计时点，或直接写"until completion of the proceedings, including enforcement"。案号与规则版本要与机构来函一致。公证、附加证明书/领事认证与官方译本等跨境形式要求以用户材料与机构实践为准提示；若某法域有强制要求，转 `11-governing-law` 并标注置信度与需外部律师意见（铁律 3、6）。
9. **对置检查**（铁律 7）：提名、问询、挑战三项各写一行"对方最可能的反驳 + 机构/仲裁庭的关注点"（如：挑战成功后的替代指定权归属、程序迟延的费用后果、我方过度挑战对后续程序裁量的影响），写入中文审阅说明。
10. **交付配对**（铁律 5）：
    ```bash
    python3 <suite>/scripts/render_docx.py --in <draft.md> --out <draft.docx> --mode legal
    python3 <suite>/scripts/verify_suite.py --workdir <案件目录> --mode submission
    ```

## 三、产出

| 文件 | 内容 |
|---|---|
| `提名/指定函` | 候选人全名、国籍、地址、邮箱、简历、同意与披露声明、可联系性 + 人数与主席机制意见 + 规则补足依据（带来源标记） |
| `披露问询函` | 时间轴化待澄清事实、具体问题清单、"行使异议权所必需"依据、答复期限与期限不计入异议期的请求 |
| `挑战申请（含标准与举证）` | 期限内提出 + 编号事实与证据 + 客观标准适用 + 规则条号与软法分类对应 + 决定机关与救济保留 |
| `中文审阅说明` | 与每份文书配对；含候选人客观要求表、失权风险时点、对置检查、权限清单缺口 |

组庭机制与确认权须按 `references/forum-rules-matrix.md` 的核验流程从本案适用版本的官方文本取得，未取文即写待核；术语对照取 `references/glossary-en-zh.md`；期限全部写入 `references/procedural-timetable.md` 口径下的时限日历。

## 四、常见错误

- 凭记忆写人数默认规则、代指天数或条号；未取得文本即引用 → 违反铁律 1、2。
- 提名函出现倾向性表述，或漏附候选人同意与披露声明。
- 收到披露函只在内部记录，未在规则期限内书面表态；或写"请仲裁庭考虑"的模糊表态。
- 未把"要求补充信息"写成行使异议权所必需，事后被指异议迟延由己方造成。
- 以商业不利、专业背景、法律观点或国籍作为挑战理由；事实不做逐条切割。
- 授权书缺"提名仲裁员/签署任务书/和解"权能，或到期日早于程序结束。
- 忽略己方提名仲裁员的披露评估：过度"沉默使用"披露在撤销阶段可能反噬。
