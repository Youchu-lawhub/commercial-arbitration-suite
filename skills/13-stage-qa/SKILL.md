# 即时问答与程序信函

本子技能是全流程的"随手问"入口，但不是免责入口：答案一样受铁律 1（版本现查）、2（来源标记）、3（不虚构）、7（对置）、8（保密）约束。涉外范围与阶段外的环节由 `route.py --scope` 和 `01-case-file` 校准，本技能不重复判定。

## 一、入口闸门

材料要求以 `suite.yaml` 的本子技能条目为唯一依据。已在会话中明确的事实直接登记，不重复索取。
对实际案件，先核对本案配置，再把已读取的材料逐项登记到案件根 `case.json`（`rulesuite-case/1`）；台账 `case` 与配置一致，Markdown 清单仅由台账生成供人阅读。

```bash
python3 <suite>/scripts/route.py --gate 13-stage-qa --workdir <案件目录> --provided <案件目录>/case.json
```

未通过时，针对影响本轮结论的缺项提问；可先整理已知事实、检索路径与明确标为未完成的框架，不虚构事实，不交付未核验定稿。通用教学或规则导航问题不要求伪造案件配置。

## 二、动作

1. **从当前待办与变化续办**。先读已有配置、当前矩阵/档案、程序地图和日历中的本轮相关记录，再对照最近来函，提取新增/已完成/阻塞项、负责人、起算文件与期限。沿用已确认事实，不重建全案；从中途接入只补影响当前决定的坐标，最多三个关键问题。紧急期限先提示核验状态与保期限动作，不因档案缺失延误提醒。
2. **判是否该转走**。
   ```bash
   python3 <suite>/scripts/route.py --match "<用户本轮原话 + 已知案件要素>"
   ```
   命中别的子技能（条款有问题 → `02-clause-diagnosis`；规则细节待查且需要成卡答复 → `03-forum-rules`；要出申请／答辩／措施 → `04`–`10`；涉外国法实体问题 → `11-governing-law`）即转交并按该子技能闸门走，本技能只做转交说明与坐标登记。返回多个候选 → 先与用户确认本轮目标，不并行开多条线。
3. **条文与指引现查**，禁止凭记忆（铁律 1）：
   ```bash
   python3 <suite>/scripts/fetch_official.py applicable --inst <机构id> --commencement <YYYY-MM-DD>
   python3 <suite>/scripts/fetch_official.py lookup <source_id> --pattern "<Rule/Section 关键词>" --max 12
   python3 <suite>/scripts/fetch_official.py fetch <source_id> --to-md
   ```
   期限类问题按"触发文件 + 实际收到日 + 条文起算口径 + 届满日"四要素计算，逐条查电子送达到达认定、期间延长、节假日顺延的本案适用条文；金额与份数从该版本费用表／规则条文取，`lookup` 未命中即标未核验，不得由近似条文推定。跨机构比较只在 `references/forum-rules-matrix.md` 的核验流程内做，两侧都须有本案适用版本的官方文本命中记录，并写明"本案适用规则以缓存文本为准"。问"这家机构有没有某机制、去哪一条找"时，先读 `assets/institutional-knowledge/` 对应册作定位导航；该册的期限与金额是上一轮核验快照，数字仍须按本步取文命中后方可写入答复。
4. **答复三段式**（固定结构，可用 `assets/templates/03-条文答案卡.md` 存档）：
   - **结论与下一步动作**：一句话结论 + 我方今天到届满日之间要做的具体动作（谁做、做什么、哪天之前）。
   - **依据**：条文／程序令／既有函件，每处带 `[source:<id> | <版本> | Art./Rule <n> | <URL> | 校验 <日期>]`；程序令原文与规则条文冲突时并列写出，不折中。
   - **对方最可能的反驳与仲裁庭关注点**（铁律 7）：对方会怎么利用这个答复（拖延、主张既成事实、反指我方迟延）、仲裁庭在意什么（比例、平等对待、时间表、既有程序令的字面表述）；期限类答复必须同时给出"我方错过该期限的后果"。
5. **判定是否升级为文书任务**。凡本轮答案会产生下列任一后果，就**不允许以口头答复收工**：对外产生义务或承诺（同意延期、认可送达方式、确认份数与格式、接受或放弃某项安排）、期限变更（申请或同意展期、新的提交日）、立场表述（保留权利、不接受管辖的初步表态、对程序事项的认可或异议）。此时转对应文书子技能，按交付契约出 `.docx` + 中文审阅说明（`12-delivery`），口头答复只作为该文书的摘要。纯内部理解性问题（这一条讲什么、现在到哪一步）才可以只答复不出文件，但答复仍要落进答案卡存档。
6. **写例行程序信函**。清单固定覆盖：延期申请与同意／反对、送达确认、抄送与份数、会议时间与形式、文件交换方式、bundle 格式、庭审出席人、费用与付款（预缴、分担、发票与税项）、保密标识、要求对方作出书面声明。统一骨架五段（`assets/templates/13-procedural-letter.md`）：**案号与主题行**（机构案件编号 + 一句事由）／**事实与日期**（只写有据可查的收发日、程序令编号、期限届满日，逐处可回溯）／**请求**（一项一请求，写清要求对方或仲裁庭做什么、何时前答复）／**保留权利**（同意某项安排不等于认可管辖、不等于放弃异议；不涉权利时也要写明本函不构成对实体问题的表态）／**抄送与附件**（是否同时抄送机构与对方、附件清单与编号）。措辞按 `references/glossary-en-zh.md` 取程序术语的通行表达，中文内部函与对外函分开写，不出一份"内外混用"的稿子。
7. **对置检查后再发**（铁律 7）：函件里每一处期限与请求旁边自查"对方最可能的回应"与"仲裁庭可能的关注点"，若我方请求会被理解为拖延，改写为更小、可即刻执行并附明确期限的请求。对方沉默是否产生后果须有规则、程序令或已达成约定依据，不能靠单方函件制造同意；延期或变更未获有效批准前仍按原期限办理。
8. **增量回写**：来函、新事实与决定先写当前矩阵/档案的来源、版本和变更理由，再刷新日历与程序地图；记录触发事件、送达凭证、时区、节假日、复核人与期限，未知写 `UNKNOWN`。渲染交付不等于实际提交，只有回执/送达凭证才能登记提交/送达完成。
   - 回款逐笔登记日期、币种、金额、凭证、分配依据与对应请求/执行目标，抵减本金、利息或费用并同步 07/09/10/14 受影响台账，跨法域禁止重复受偿；无确认汇率分币种列示。T 主表只在执行矩阵，不复制资产底账。
   - 新材料改变 E/F/EV/R/A 或原结论时，交原上游仅重核受影响部分；独立 02/14 不补建 case 矩阵。每轮结尾列下一动作、负责人、时间依据、阻塞与待批准事项。
9. **保密**（铁律 8）：函件与文件名不暴露对方身份与争议标的细节；往来原件与送达凭证只写用户指定案件目录。

## 四、常见错误

- 无坐标就答期限：用发出日而非规则规定的送达／收件日起算，或漏掉期间延长与节假日顺延。
- 凭记忆写条文号、费用档位、份数与天数，把另一版规则或另一机构的默认值当作本案规则（铁律 1）。
- 该出函的只给了口头意见——我方"同意"没有落成书面文件，事后被对方主张既成事实，或我方权利因未书面保留而流失。
- 信函把"同意某项程序安排"写成对管辖权或实体问题的表态，丢掉保留权利段。
- 一函多个请求、无明确答复期限，对方与仲裁庭各自理解；抄送范围与份数口径没写清。
- 答复只给单方乐观结论，不写对方反驳与仲裁庭关注点（铁律 7）。
- 函发出去不回写日历与程序地图，下一轮又从头判断处于哪一步，重复劳动并漏掉新期限。
- 缺料时靠推测补齐主体、日期或金额（铁律 3），或把案件材料写到技能包目录里（铁律 8）。
