# 答辩、反请求与管辖权异议

我方为被申请人。涉外范围与阶段坐标先由 `scripts/route.py --scope` 与 `01-case-file` 确认（铁律 0），本文件不重述。

## 一、入口闸门

材料与入口闸门以 `suite.yaml` 本子技能条目为准（铁律 3、4）；已明确的事实直接登记，不重复索取。
已读取材料登记到案件根 `case.json`（`rulesuite-case/1`，台账口径见 `references/practical-workflow.md`）。

```bash
python3 <suite>/scripts/route.py --gate 05-defence --profile <文书类型> --workdir <案件目录> --provided <案件目录>/case.json
```

本子技能任务类型：`answer`、`counterclaim`、`jurisdiction`。只选本轮需要的文书类型，不把其他类型的必填项合并进来。

未通过时只追问影响本轮结论的缺项；可先出未完成标记的框架，不虚构事实（铁律 3）。

## 二、动作

- 先读取当前 `案件档案/case-matrix.yaml`（schema 2）与 `references/case-construction.md`，逐项从对方命题/要件连接 DF、F、EV、A；反请求另以 CL 连接 E 与实际 R，不另建事实底账。
- 记稿声明 `workflow: 05-defence`、所选 `profile: answer|counterclaim|jurisdiction`（三选一）、`matrix: case`，`case` 仅写稳定代号。纯否认答辩可无本方 CL/R，不虚构己方举证要件；指明对方未证事项即可。
- 事实与实质论证段附近写内部追溯行，例如 `#! 锚点：F-001 / E-DF01-01 / EV-001 / A-01`；有实际救济才关联 R，只填矩阵真实 ID，F/E/EV/R/A 无关组省略，不用 `[[F]]` 或 `[[F-001]]`。EV 与卷宗附件号分存，`#!` 不进入 Word。
- 起草前、提交前留存 AT/PM 对抗审查，检验对方最强论证及我方回应、备位与残余风险；自审标 `self_review`，不冒充独立审查。
- 非金钱请求/抗辩不强迫金额、币种或利息；不因模板有反请求栏就要求反请求。新证据先回写矩阵，OQ 与 `pending.json` 中 Q 占位分开。
- 交 12 前用 `case_matrix.py anchors --in <矩阵路径> --draft <文书.md>` 回查，并以 `check --in <矩阵路径> --stage draft|submission` 选本轮阶段；缺口不牵连无关 profile。

1. **锁期限（确定性动作，禁凭记忆）**：先从机构通知、适用规则与送达凭证确定触发事件及起算日；快递、邮件、内部 OA 时间分别保留，不机械取最晚日，也不混同发函、提交或收件日。期限长度、次日起算、节假日/非营业日顺延、多被申请人分别或共同起算、电子送达与时区——逐条从本案适用规则及指令核实，未核先提示潜在最早期限：
   ```bash
   python3 <suite>/scripts/fetch_official.py applicable --inst <机构id> --commencement <YYYY-MM-DD>
   python3 <suite>/scripts/fetch_official.py lookup <规则版source_id> --pattern "Answer|counterclaim|time limit" --max 12
   ```
   缓存缺失（`NOT_CACHED`）先 `fetch <source_id> --to-md` 或引导用户人工下载；拿到文本前不得落任何条号。产出一行期限结论并写入时限日历：`届满日 + 起算日与凭证 + 依据 Rule <n> + [source:… | 版本 | Rule n | URL | 校验日]`（铁律 1、2）。期限倒排内部截稿，提前量不少于工作日的三分之一。
2. **建逐条对应表**：以申请书段落号为行，每行只取三种状态之一——`admitted` / `denied` / `no admission made`（后者用于我方尚无信息且不愿推定事实的行）。禁止"全部否认"式偷懒：沉默回避某项管辖或事实问题，事后会被认定为接受。不承认的粒度精确到可分割最小单元：把"合同签署＋收到货物＋欠款金额"这类合并句拆成单独行分别定态，一处过度承认后续无法撤回。
3. **选开局策略**（三种，判据如下）：
   | 策略 | 文书 | 适用判据 |
   |---|---|---|
   | 实体详析答复 | `assets/templates/05-answer-to-request.md` | 材料基本齐、条款与主体无根本争议、需在组庭前建立案情强度印象 |
   | 延期申请（保期限） | `assets/templates/13-procedural-letter.md` | 材料未齐或内部审批未完；给具体届满日或天数并说明规模与复杂性理由，一次要够，多次追加损害合作性评价 |
   | 极简答复且明示不构成接受管辖 | `assets/templates/05-answer-to-request.md`（简版） | 主张不存在有效仲裁协议／我方非条款约束方；一切表述用条件句（"in the event that…"），并保留管辖与可受理性异议 |
   延期与极简两式仍须在同一原期限内满足规则最低必载项：**仲裁员人数与提名表态**（以及规则要求的主席产生方式意见、对适用规则版本的表态）。理由是这些权利按期限失权，机构可在我方沉默时径行按对方主张推进组庭，提名机会与三人庭结构事后不可复原。
4. **写管辖与可受理性异议**（`assets/templates/05-jurisdiction-objection.md`）：按层递进，逐层各自给证据锚点——① 仲裁协议是否存在（签署、成立）；② 是否有效/可执行（形式、可仲裁性、条款自治性）；③ 是否涵盖本案争议（多合同对应表、条款适用范围）；④ 本案当事人是否受条款约束（签约方、集团架构、加入关系）；⑤ 条款前置条件是否成就（协商期、调解期、期限）。机构此阶段仅作表见（prima facie）判断，最终由仲裁庭裁；因此每一层都要"提出 + 保留"：此刻明确提出 jurisdictional / admissibility objection，并写明本答复及参与程序的任何行为均不构成对管辖的接受、异议将在任务书与实体书状阶段重复。涉及境外法对协议效力、可仲裁性的结论一律转 `skills/11-governing-law` 分层标注置信度并注明需外部律师意见，本文件不作实体法教义判断。
5. **决定是否提出反请求**：分别选择不提出、同时提出或依法保留以后提出；不能把纯否认改成承诺反请求。核验本案适用规则、程序令及实际阶段对新增请求的期限与许可要求，不默认存在任务书。同提时用 `assets/templates/05-counterclaim.md`，反请求须自足地支撑管辖、责任和所求救济；核条款及主体范围，金钱请求附量化台账，非金钱请求明确对象、行为、范围和期限，预缴及提交方式另核。确有后续提出意图时才如实表态，保留措辞不替代期限遵守或所需许可。
6. **责任抗辩与救济范围抗辩并行**：按材料提出可支持的备位论证；金钱争点可写"即使责任成立，上限亦仅为 X"，非金钱争点核对象、范围、履行条件与期限，不强造金额；对对方金额量化逐项提具体异议（重复计算、未扣已付、汇率与期间错配、选择性请求只按主请求计），该异议同时影响费用档级与后续担保费用的计算基数，不能只在实体段一笔带过。
7. **程序事项一并表态**：仲裁地、语言、准据法立场各给可操作理由（文件语言、证人语言、执行地、中立性），情绪化偏好无效；预告文件披露、临时措施与担保费用申请，为时间表阶段争取期间。
8. **对置检查**（铁律 7）：对期限、管辖、反请求、金额四项各写一行"对方最可能的反驳 + 仲裁庭的关注点"，删除任何单方乐观结论；中文文书落在矩阵 `adversarial_review`，非中文文书再在中文审阅说明复述。
9. **交付配对**（铁律 5）：非中文文书才配同名《中文审阅说明》（`assets/templates/12-中文审阅说明.md`，五节固定），中文答辩状不另出：
   ```bash
   python3 <suite>/scripts/render_docx.py --in <draft.md> --out <draft.docx> --mode legal
   python3 <suite>/scripts/verify_suite.py --workdir <案件目录> --mode submission
   ```
   提交前再核规则现查的递交要求：份数、递交渠道、是否须同时向对方送达并附送达说明。

## 三、产出

| 文件 | 内容 |
|---|---|
| `Answer to Request for Arbitration` | 三态逐条对应 + 己方时间线 + 管辖异议（提出+保留）+ 组庭/仲裁地/语言表态 + 保留权利主文 |
| `Counterclaim（如有）` | 自足的事实、责任、金额分项台账、主文 |
| `管辖权/可受理性异议（保留权利写法）` | 五层论证 + 明示不构成接受管辖 + 重复与保留声明；可与答复合并或另函 |
| `中文审阅说明`（仅非中文文书） | 与该文书一一配对；含策略选型理由、期限凭证、对置检查、待用户确认事项 |

术语与中英表述对照取 `references/glossary-en-zh.md`；答辩与反请求期限、失权后果须按 `references/forum-rules-matrix.md` 的核验流程从本案适用版本的官方文本取得，未取文即写待核，不引用任何预存条号或天数。

## 四、常见错误

- 期限按发函日推算、或按记忆写天数；届满日无来源标记 → 违反铁律 1、2。
- 把延期申请当成全部答复，漏掉人数与提名表态，提名权失权。
- 为求简洁写出"本仲裁中的……"这类无条件表述，被援引为同意管辖。
- 合并句里作出事实承认（收到货物、欠款数额），后续无法撤回。
- 反请求只写请求不写事实与计算，补正时已逾期；或未核是否受同一条款约束。
- 管辖异议只写结论不写分层与证据锚点；或只在内部记录未书面提交。
- 否认未指明对方未证的命题/要件；为凑己方版本而虚构事实、积极抗辩或反请求。纯否认本身不要求本方 CL/R。
- 金额估算与责任立场互相矛盾（同一事件两处不同日期或口径）。
