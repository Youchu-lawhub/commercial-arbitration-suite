# 证据：披露、证人、专家

本子技能只管证据怎么取得、怎么固定、怎么被采纳。披露制度的既载约束以本案程序令文本为准；涉外范围已由 `python3 <suite>/scripts/route.py --scope` 在 `00-cold-start` 判定，本轮再遇纯境内或劳动争议要素即退回铁律 0，不开工。

## 一、入口闸门

材料要求以 `suite.yaml` 的本子技能条目为唯一依据。已在会话中明确的事实直接登记，不重复索取。
对实际案件，先核对本案配置，再把已读取的材料逐项登记到案件根 `case.json`（`rulesuite-case/1`）；台账 `case` 与配置一致，Markdown 清单仅由台账生成供人阅读。

```bash
python3 <suite>/scripts/route.py --gate 08-evidence --profile <文书类型> --workdir <案件目录> --provided <案件目录>/case.json
```

本子技能任务类型：`production`、`witness`、`expert`。只选本轮需要的文书类型，不把其他类型的必填项合并进来。

未通过时，针对影响本轮结论的缺项提问；可先整理已知事实、检索路径与明确标为未完成的框架，不虚构事实，不交付未核验定稿。通用教学或规则导航问题不要求伪造案件配置。

## 二、动作

- 先读取当前 `案件档案/case-matrix.yaml`（schema 2）及 `references/case-construction.md`，围绕本轮 E 的证据/缺口规划披露、证人或专家，不另建事实底账。
- 记稿声明 `workflow: 08-evidence`、所选 `profile: production|witness|expert`（三选一）、`matrix: case`；`case` 仅写稳定代号，拆件保留其适用元数据。
- 事实、论证段附近用内部追溯行，如 `#! 锚点：F-001 / E-CL01-01 / EV-001 / A-01`；仅列真实依赖的 F/E/EV/R/A，不用 `[[F]]` 或 `[[F-001]]`。表格不强制逐格锚点，但底稿保留请求/证言/专家输入与矩阵的映射；`#!` 不进 Word，EV 与附件号分存。
- 证人亲历/转述、专家假设/数据与既证事实分开；新证据先更新矩阵来源、证明范围、不利事实及缺口，不把预期证言写成已证事实。程序证据可记程序用途，不强造实体 E。
- 纯否认答辩的取证不强造本方 CL/R；非金钱事项不强加币种、金额或利息。OQ 与草案 `pending.json` 的 Q 占位分别跟踪。
- 提交前留存 AT/PM 对抗审查，覆盖相关性、证明力、特权、专家假设及最强反驳；自审标 `self_review`。用 `case_matrix.py anchors --in <矩阵路径> --draft <文书.md>` 与 `check --in <矩阵路径> --stage draft|submission` 选本轮阶段，再交 12。

1. **锁定时点与权限**：核对当前阶段、适用规则、程序令及本轮截止日。书状未交换或争点尚未展开时，说明取证的具体必要性；紧急证据保存、早期披露与常规披露分别判断，不以预设时间表排除申请。
2. **先建三栏底稿**：任一方的争点／要件及书状定位 → 待证明或反驳的事实 → 所需特定文件或文件类别。尚无书状时用案件矩阵定位事实与程序用途，不虚构段落号。相关性与重要性分写，不以对方未主动论述该文件为由拒绝取证。
3. **按可识别程度写请求**：能识别特定文件的，写明名称、日期、制作人等特征；需要类别的，限定主体、类型、时段及事由。说明相信文件处于对方占有、保管或控制下的事实依据，关联关系不当然等于控制；采用本案适用的提出请求标准，不要求先证明尚待披露的内容。
4. **比例与负担**：评估请求范围、检索负担、证明价值及替代途径，必要时缩窄、抽样或分阶段。己方持有情况如实说明；对等披露、放弃异议或保密让步须经用户确认，不写成默认承诺。
5. **表格与裁定分工**：采用程序令规定的列数与格式；未规定时可提出五列 Redfern 表。每项请求提供足够的独立理由，清楚的交叉引用不自动等于空白。决定栏由仲裁庭填写，合并表不表示双方已同意未决内容。
6. **异议与特权**：按本案适用标准审查特权主体、法律基础、披露例外及证明要求。可请求特权日志或合理检索说明，内容须足以审查而不泄露所保护的信息；是否要求逐件、按类或由独立人员审查须另核，不能仅因未交日志认定特权丧失。既有裁定按其理由及事实范围使用。
7. **保密方案**：明确保护对象、可访问人员、用途、复制、庭审引用和向专家／证人提供的条件。逐项考虑法定义务、法律权利维护、裁决救济及执行所需披露例外；通知义务不得妨碍法律禁止通知的情形。保密协议、拟议程序令和已签发程序令分开，不以当事人协议当然约束机构或仲裁庭。
8. **未披露的后果**：核验不利推定等措施的依据与条件，包括文件控制、命令范围、未履行理由及陈述机会，再提出与待证事实相关的具体请求。期限届满及时记录并跟进，但不把未在当日跟进等同于权利丧失，不自动转移举证责任。
9. **证人陈述**：记录身份关系、亲历事实、转述来源、所用文件、补偿情况及适用的声明签署要求。区分事实与意见，不代写应答脚本或诱导证言；补充或更正以允许的程序保留版本及原因。证人不是任何一方所有，接触限制依适用伦理规范、法律与程序令核验，不阻碍依法接触或作证。
10. **庭前准备**：区分允许的程序说明、材料复核与禁止的证言塑造；不确定时转 `11-governing-law` 并必要时请求程序指示。内部准备材料是否受特权保护或可能须披露另行判断，标注保密不等于当然免于披露。
11. **专家机制**：按争点所需专门知识确定领域，例如损失量化、工程技术、会计估值或外国法，不以示例穷尽范围。核验指定方式、独立性、适用职责、职权范围、共同问题与数据；联合会议应真实记录共识和分歧，不人为统一结论。
12. **外国法专家**：涉及外国法存在、内容或其证明方式时进入 `11-governing-law`，核对适用方法和原始权威，不把专家意见本身当作法源已核验。
13. **对置检查**（铁律 7）：每项请求与异议记录对方最强反驳、仲裁庭可能关注的比例与平等问题、可接受缩窄方案及其对要件证明的影响；缺口先补，不用固定套话代替判断。

## 四、常见错误

- 不核程序窗口与紧急性，机械拒绝早期取证或机械套用首轮书状后的时间表。
- 请求范围过宽而不说明证明价值、检索负担及替代途径。
- 只写“与案情相关”，没有连接任一方具体争点、要件或程序用途。
- 未说明文件持有或控制的事实基础，或重复请求却不说明必要性。
- 把拟议表格格式、日志或程序令写成已经生效的强制要求。
- 将未提供特权日志直接当作放弃特权，不核适用标准及审查措施。
- 限定代理人查阅却未解决专家与当事人陈述案件所需的访问。
- 证人陈述写成律师论辩口吻、多份陈述同一日期细节互相矛盾、律师代签或改动无留痕。
- 未确认庭前证人准备的允许范围，庭中被指不当接触，连累全部证言可信度。
- 对特权文件的请求引发对等报复性请求，己方内部法务沟通暴露面反而更大（起草前先自查己方文件生态）。
- 用大量请求赌命中率，或被驳回后在第四栏攻击对方诚信，降低整体说服力。
