# 裁决救济与终局性

先保护最近的程序窗口，再读完整裁决与付款情况。区分“期限尚未核验”和“期限不存在”；不预测胜诉率、回收率或法院结果。给中国企业法务的一页结论先写最近期限／核验任务、可选动作及代价、最多 3 项待决定事项，不把管理层简报设为每次任务前置。

## 一、任务与入口

| profile | 本轮目标 |
|---|---|
| `matrix` | 日期、三类日历、逐份裁决及动作底账 |
| `correction` | 更正、解释或补充裁决申请；先定性，再选标题 |
| `set-aside` | 撤销事由、期限、弃权与执行地对置决策 memo |
| `finality` | 每份文书的性质、已决／未决事项、独立挑战与执行可用性 |
| `settlement` | 履行和解、保留既有裁决、担保与可能的合意裁决路线 |
| `enforcement-triage` | 一页执行初筛与向 14 转交 |
| `enforcement` | 保留旧入口，按 enforcement-triage 处理并转 14 |

已在会话中明确的事实直接登记。实际案件核对配置与 `case.json` 案件代号；只要求本 profile 所需材料，未齐时给定向补料、核验请求与受控草案，不发布未经核验的可提交版本。

```bash
python3 <suite>/scripts/route.py --gate 10-award-post --profile matrix --workdir <案件目录> --provided <案件目录>/case.json
```

## 二、十二步处理

### 1. 登记日期与证据

分别登记裁决作出日、机构转交日、我方实际收到日；另记对方收到日、约定或裁定的履行期及更正文件收到日。保存正本、机构通知、快递凭证、信封及邮件时间戳。每个日期说明可能触发的程序，不能把作出日、送达日和收到日互换。

### 2. 三个日历保持独立

更正／解释／补充、撤销、承认与执行分别列：裁决 ID、法域、期限名称、期间、起算事件及证据、届满日、时区／节假日口径、可否延展、提交对象、份数／附件、负责人、复核人、依据。未核验的法定期限写 unknown；内部核验截止日与法定届满日分开。更正申请是否影响其他期限逐一核验，不推定重启或停止。

机构规则按约定、启动日和过渡条款确定版本后用 `fetch_official.py applicable / fetch / lookup` 查原文；法院期限按裁决分类与当地现行法查。使用 `references/global-research-protocol.md`；`references/asia-jurisdictions.md` 仅作区域入口。所有具体命题保留 `[source:<id> | <版本> | <页条段> | <已核验URL> | 校验 <日期>]`，境外法结论转 11 或当地律师。执行期限由 14 逐地核验后回填，不在此另造一套。

### 3. 清点每份文书并判断终局性

部分、管辖权中间、费用、最终、合意、补充裁决与更正／解释文书逐件编号为 AW-，不占用 A- 权威主键。逐份登记性质、已决事项、终局拘束力、保留未决事项、是否构成当地法下可独立挑战的裁决、是否有其他即时救济、是否可承认执行及各自窗口。**逐份评估不等于每份都可单独撤销**；不能只凭标题判断，也不能等最终裁决才查所有期限。

### 4. 裁决要点核对

逐格写裁决页段与材料依据：

- 主体与主文义务能否确定：谁、履行什么、币种、金额／计算方法、履行时间、必要支付路径；缺账户不当然使裁决不可执行，按目标地要求判断。
- 本金、利息、费用分列；利率依据、基数、起算／截止、单复利、汇率日期；核对实际已付款与抵减，避免重复主张。
- 机构／仲裁员费用、代理及专家费用由谁核定、预付款结算及余额；不要预设所有机构相同。
- 已提出请求、裁决理由与主文对应；区分漏裁请求、未逐一讨论的论点、超出范围的裁断。
- 签署人数、未签说明、法律仲裁地、实际签署地、理由及机构核阅要求；异地签字本身不等于程序违法。
- 异议意见是否合法可得、能证明何事；不凭异议存在推定裁决无效，不无依据索取受保护评议材料。

### 5. 更正、解释与补充

先查本案适用规则与仲裁地法的授权、对象、当事人约定条件、时限和程序：

| 路线 | 需要证明 | 不要混入 |
|---|---|---|
| 更正 | 算术、笔误、抄写或规则允许的类似错误；原文／拟改文字数字／凭证与计算底稿 | 重新评判已决事实或法律 |
| 解释 | 适用规则允许解释的具体部分及真实歧义，两种读法与实际影响 | 因不满意理由而要求重新裁判 |
| 补充裁决 | 确实已提出、未裁断且可通过补充处理的请求；请求书状与裁决对照 | 新请求、已被驳回的请求或借漏裁名义重审 |

更正及解释对象**不一律限于主文**，按适用规则核验。补充裁决可能需要审理漏裁请求，不把它错误限制为“只能说明既判内容”。上诉、撤销、发回或重开也须查是否存在，不能把实体不服自动转为可行救济。

核验庭方主动动作与当事人申请的不同起算、转送程序和份数。成立或驳回使用何种文书、是否成为裁决一部分、是否引发新的挑战窗口，均现查；不静态断言 addendum／decision 的统一效果。相关请求可依法合并说明，不机械规定一裁决只能一份申请；避免重复或拖延性提交。

### 6. 撤销事由与权利保留

按仲裁地法核验可用事由：协议／能力、通知与陈述机会、超裁、组庭或程序、独立公正、可仲裁性、公共政策等；这些是研究起点，不是跨法域通用法定清单。记录法定要件、举证责任、事实与异议时点、已知障碍及反方最强回应。单纯实体不服不当然构成撤销事由。

核查何时知悉瑕疵、何时及向谁提出异议、程序令如何处理、是否构成弃权及例外。未异议不自动丧失一切救济，更不能据此推断去执行地抗辩更好。期限、延展与中止逐地确认；不引用未经核验的整体成功率。

### 7. 撤销地与执行地对置

在内部 memo 比较撤销、执行地抗辩及可能的协调并行路线：事由、举证、弃权／既判影响、期限、成本、中止与担保、对既有执行的效果。借用 14 的目标初筛，不重新展开执行矩阵。**撤销成功不当然切断全球执行；未撤销、撤销失败或一地拒绝承认也不当然决定其他法院结果。** 查相关法域对撤销裁决、纽约公约第 V(1)(e)、VI 条及更有利规则的适用，不作跨国概括。

### 8. 执行初筛并转 14

仅登记债务人、裁决余额、已付款、可能资产／法域、当前执行状态、最紧急障碍、需要核验的问题及转交人。资产未知可转 14 的 asset 或 counsel，不虚构 T- 可执行目标。不在 10 复制逐地文件包、资产调查、保全、成本和董事会全文。

### 9. 专项变量分流

国家／国企／主权基金触发身份与资产分析，不自动赋予豁免；管辖与执行豁免分开。破产申请、受理、开庭、承认与中止分别登记，不能推定全球中止或执行当然让位。将专项交 14 的 immunity／insolvency，资产转移紧迫措施交 14 与 07，日期与对撤销窗口的影响回填此处。

### 10. 裁决后和解与费用收口

先确认仲裁庭是否仍有权限、程序是否终结、当事人同意与适用法是否允许合意裁决；不能默认随时补一份新裁决。比较履行和解、保留既有裁决并分期付款、托管／担保、其他合法执行文书；普通和解与终止令不因名称变成纽约公约裁决，但可能有独立合同、调解或本地执行路径，需另核适用条件。

明确结构化付款、加速条件、利息、担保签署与权限、违约后果、释放及撤回执行条件、债务更新风险、反请求、税务与保密。**未取得约定履行／有效担保前，不为取得新裁决先释放旧裁决或权利。** 各国收款进入同一抵减底账；担保人与非当事人的义务不得凭和解措辞强加。

费用争议独立核对机构已核费用、庭方可裁费用、预缴款退款及税费；保留庭方费用管辖或另行解决均先核权限与合意，不当然另组费用仲裁庭。未缴预缴导致终止时保留通知、说明与协商记录。

### 11. 外部律师指示

使用 10 指示模板处理更正、撤销、终局性及庭权；执行问题用 14 指示模板。逐问列法域、最小事实与未知、所需交付和权威层级、预算／报价授权、截止日。允许把“法院、期限和材料要求尚不确定”作为核验问题发出，不能先要求得到答案才委托律师。只把实际核验的来源列已查，不把未问事项写为全部已核验；允许指出资料失效、反向权威与适用性问题。回件登记来源、版本、置信度、限制与进一步动作，不索要胜率。

### 12. 交付与回写

事实、要件及证据沿用 `case-matrix.yaml`（新案 `schema: 2`）；执行底账由 `enforcement-plan.yaml`（`schema: 1`）维护。实质段落用 `#! 锚点：F-001 / E-CL01-01 / CL-01 / DF-01 / R-01 / EV-001 / A-01` 形式，替换为已存在且相关的 ID；AW-/T- 只作表内文书／目标编号，不作案件段落锚点。

对外申请及律师指示为非中文时配《中文审阅说明》，本身用中文起草的法院申请或函件不另出；内部矩阵／分析／和解方案 `pair: false`。内部反方攻击、谈判退出线与授权上限不混入公开申请；给律师的必要披露需授权且限于本次范围。保留有效法律引注，内部分析不整份随申请外发。

```bash
python3 <suite>/scripts/case_matrix.py check --in <案件档案/case-matrix.yaml> --stage draft --profile correction --json
python3 <suite>/scripts/case_matrix.py anchors --in <案件档案/case-matrix.yaml> --draft <交付目录/更正申请.md> --json
python3 <suite>/scripts/render_docx.py --in <交付目录/更正申请.md> --out <交付目录/更正申请.docx> --mode legal
python3 <suite>/scripts/verify_suite.py --workdir <案件目录> --mode submission
```

只对使用案件矩阵的任务运行相应检查；提交申请前同时核实期限、权限、对象、送达、附件与用户批准。矩阵 check 的阶段为 draft／submission，不设 enforcement 阶段；执行 filing 核验交 14。受控草案对应 verify 的 draft；脚本未通过不得声称可提交。
